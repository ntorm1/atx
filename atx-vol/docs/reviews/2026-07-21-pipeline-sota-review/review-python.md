## 1. CORRECTNESS — ranked defects

### P1

1. **`AtxError` loses the structured error code** — `src/bindings/module.cpp:21-30`, `src/bindings/result.hpp:11-20`. `AtxException` carries `code_` (`atx::core::ErrorCode`) and the module even binds the `ErrorCode` enum (`pricing.cpp:117-128`), but the translator does `py::set_error(exc, error.what())` — string only. There is no `.code` attribute on the raised Python exception; the library's own test resorts to regex matching (`tests/test_atxvol.py:100` `match="InvalidArgument"`). Failure scenario: any programmatic error dispatch (retry on `Unavailable`, skip on `NotFound`) must parse prose that is not a stable contract. Fix is standard pybind11 custom-exception-with-attributes; the enum is already bound.

2. **`ts_ns` corrupted on TSV read-back** — `src/atxvol/report/io.py:74`: `result.ts_ns = [int(float(r[ti])) for r in rows]`. The C++ writer emits `ts_ns` as `%lld` integer text (`src/tearsheet.cpp:243`), but the reader routes it through `float()`. Nanosecond epochs (~1.7e18, the fixture's own `BASE_TS`) exceed 2^53; ulp there is 256, so round-tripped timestamps are silently off by up to ±128 ns. This breaks the module's headline "bit-exact round-trip" claim for the one int64 column. The round-trip test uses `ts_ns=[1,2,3]` (`tests/test_report.py:186`) so it cannot catch it. Fix: `int(r[ti])`.

3. **`implied_vol_batch` throws away the whole batch on one bad lane** — `src/bindings/pricing.cpp:88-95`. Per-lane statuses are checked and the *first* failure raises `AtxError`, discarding every successfully inverted vol and every other lane's diagnosis. Real NBBO chains routinely contain uninvertible quotes (price below intrinsic, crossed markets), so on production data the vectorized IV path is effectively unusable — the exact workload it exists for. Vola's convention (NaN + status array) is what the C++ layer itself provides (`batch.hpp:102` parallel-status convention); the binding erases it.

4. **Friction-regime labeling is NOT enforced in `atxvol.report`** — the sprint deliverable "WS-X-B makes regime the first key of every artifact … a renderer that hard-refuses a track with no `friction_regime`" (`sprints/2026-07-19-spy-dispersion-hotpath-sprint-STATUS.md:240-244`) exists only in commit `f2b0f68`, which is **not an ancestor of main** (verified: `git merge-base --is-ancestor` → NOT_IN_MAIN; `friction_regime` greps to zero source hits on main). `atxvol.report.dispersion.build_report_from_run` (`report/dispersion.py:70-86`) renders any track with no regime key, no banner, no refusal; neither `components.py` nor `theme.py` has a regime affordance. Per the sprint's own numbers the headline is ~95% friction-dominated and flips sign under modest impact — this renderer will happily produce an unqualified frictionless "+$247" report. Failure scenario is exactly the one the sprint called "misleading."

### P2

5. **`AloPricer.price` releases the GIL around a mutating call** — `pricing.cpp:204` uses `py::call_guard<py::gil_scoped_release>`; `AloPricer::price(double)` is non-const (`american.hpp:296`, cached-boundary mutation). Two Python threads sharing one pricer race in C++ with no lock and no GIL — UB. Either drop the release or document/lock.
6. **`to_dict` signal-name collision** — `backtest.cpp:319-322`: signals are folded into the same dict namespace as the 28 fixed columns; a strategy signal named `nav` or `cost` silently overwrites the engine column. Prefix or nest them.
7. **Shared `SnapshotCache` across concurrent `run_backtest` calls** — `backtest.cpp:353-360` releases the GIL with a user-supplied `RunConfig.snapshot_cache` (shared_ptr, `backtest.cpp:219`); nothing in the binding prevents two threads from running two backtests over one cache. The engine's own recent history (WS-ZCFIX `e0da68b`, "seal only the snapshot cache run_backtest privately owns") shows this seam is delicate.
8. **HTML injection from run artifacts** — `report/dispersion.py:129-137` interpolates `spec` values (read from `run_spec.tsv` / TSV meta) unescaped into the colophon; `Note`, `Figure.caption/subtitle`, `Section.lede`, `Report.standfirst` are raw-markup by design (`components.py:77,106,218,237`). Table cells and titles are escaped; the spec/colophon channel is not. A `<`-containing path corrupts the document.
9. **`_render` crashes on an empty result** — `report/dispersion.py:219` `cumulative[-1]` IndexError when n=0 (also `dates[0]` is guarded but `nav_rows`/axes are not). A zero-row track should render a stub or raise cleanly.
10. **`read_kv_tsv` header heuristic** — `io.py:95`: skips the `key\tvalue` header only if it is literally line 0; a leading comment line causes `{"key": "value"}` to enter the spec dict.
11. **`write_backtest_pnl_tsv` meta unsanitized** — `analytics.cpp:26-46` stringifies arbitrary objects; a value containing `\n` or `\t` corrupts the `# key=value` header the reader then misparses.
12. **Pybind default-arg conversion at def time** — `RunConfig{}` (`backtest.cpp:359`), `DispersionBacktestConfig{}` (`dispersion.cpp:157,168`), `ArchiveV2WriteOpts{}` / `SurfaceDbCreateOpts{}` (`surface_db.cpp`) are converted once and shared across calls. Currently benign (never mutated internally), but these are mutable bound types — a latent footgun. The module.cpp registration-order comments (module.cpp:33-46) show the authors know this class of issue; worth the same care here.

### Things checked and found sound
- `Result<T>`→exception: `unwrap` moves, translator chain correct; error *message* (including code name via `to_string()`) survives.
- Lifetimes: `DeclarativeStrategy.spec` and `PricedSurface.pricing` use `reference_internal`; `Clock` copies `SnapshotRef`s; `SurfaceDb.load_surface` returns an **owned** `PricedSurface` (`surface_db.hpp:471`) — no dangling into the partition cache; `write_partition` (`surface_db.cpp:40-70`) correctly pre-reserves the symbol vector to keep `string_view`s stable and holds the Python list across the GIL release; `PricedSurface.create` guards double-consumption of the moved-from `CurveSurface` (`surface_db.cpp:145-148`).
- GIL: `run_backtest` releases the GIL and the strategy is pure C++ — no deadlock; batch kernels write into preallocated numpy buffers under released GIL without touching Python API.
- `backtest_util.hpp::require_consistent` converts the ragged-result access violation into `ValueError` before every consumer — good, and tested (`test_report.py:153-167`).
- Numeric defaults audited against C++ (`baw_american` 16/1e-8, `american_implied_vol` 1e-7/64/0.0, `black76_value_and_vega` sqrt_t=-1 sentinel) — all match.

## 2. PERFORMANCE

- **No vectorized path for anything American.** The C++ SoA laned AVX2 flagship (`american_batch.hpp`: `american_price_batch`, `american_greeks_batch`, `PricingKernel`) is entirely unbound; so are `black76_greeks_batch`, `black76_value_and_vega_batch`, `black76_price_from_lnfk_batch` (`batch.hpp:65-123`) and the strike-axis American IV batch (`american_iv.hpp:88+`). From Python the only batch entry points are B76 price, B76 IV, one-slice `essvi_w_batch`, and `american_price_slice` (boundary-reuse across strikes, single expiry). Everything else — `american_greeks_al`, `PricedSurface.fair_value/greeks/delta/vega`, `VolSurface.iv` — is scalar-per-call: ~1–2 µs pybind dispatch (+GIL release/reacquire on the scalar defs, which for a ~50 ns `black76_price` is pure overhead, `pricing.cpp:206-215`) versus sub-µs kernels. Chain-scale valuation from Python is a Python for-loop, 10–100× off the C++ hot path. This is the single biggest gap vs a Vola-style numpy-native API.
- `PricedSurface` query methods and `SurfaceDb.load_surface` hold the GIL (`surface_db.cpp:155-199, 255-259`) — surface queries can't be parallelized from Python threads, and archive loads block the interpreter (disk I/O + deserialize).
- Copies: `BacktestResult` columns are memcpy'd to fresh numpy arrays on **every** attribute access (`backtest.cpp:34-61`), and setters go through element-wise `std::vector` casts. Fine at track scale (10³–10⁴ rows), wrong pattern if columns grow. `to_dict` copies all ~28 columns; called once per report — fine.
- Report generation: pure-Python string assembly, one hover `<rect>` per sample per chart plus a full per-session HTML table (`dispersion.py:163-168`); linear and acceptable to a few thousand sessions, no caching issues.

## 3. FEATURE GAPS

**Coverage: ~25 of ~90 public headers; the entire front half of the canonical lifecycle is unreachable from Python.** The umbrella's blessed path (`vol.hpp:33-60`) is chain → fit → priced surface → archive → book; Python gets only "priced surface (hand-authored parametric) → archive → backtest." Unbound, by area:
- **Fitting/calibration: 0%.** No `VolaSession` (`session.hpp:396` — `from_frame`, `iv`, `fair_value`, ladders, `refit_slice`, `to_priced_surface`), no `PricerFitter`/`FittedSurface`/`value_chain`/`OutputField` (`pricer_fitter.hpp:374+`), no `OptionChain`/`MarketEnv` (`chain.hpp`), no `essvi_calib`/`svi_calib`/`c8`/`cstar`/`curve_fit`/`curve_selector`/`fit_policy`/`arb`/`deamer`/`dividend`/`parity`. **A quant cannot fit a surface from quotes in Python** — the core competitive claim against Vola Dynamics (fast, arb-free fitting) has no Python surface at all.
- **Data model: ~0%.** No `QuoteFrame`, `OpraPanel` loader, `panel`, `listed_opra`, `occ_ess`, `universe.hpp` proper (only `canonical_symbol`).
- **Portfolio/risk: 0%.** Neither the canonical `PortfolioPricer` (price + Taylor PnL-explain) nor the legacy engine, no `scenario_grid`, no `analytics.hpp`, no `projection`/`contract_projection`/`derivatives`.
- **Archives: write-only.** `ArchiveV2WriteOpts` is bound; `SurfaceArchive::open`/`map_symbol` (read side) is not — only via `SurfaceDb`.
- **`IStrategy` is exposed but not subclassable** (`strategy.cpp:150`, no trampoline, no init): Python-defined strategies are impossible; attempting it fails at construction. Fine for now but the class's presence invites it.
- **Curve kinds:** only `push_essvi`/`push_svi` (`surface_db.cpp:110-124`); `ConvexDense`, `C8`, `SplineVol`, `LinearVariance` curves cannot be authored from Python though the enum lists them.

**Packaging maturity: prototype.** `pyproject.toml` hardcodes `clang-cl` + `x64-windows` vcpkg triplet in global defines — the sdist cannot build on Linux/macOS as configured. No wheels/CI, no abi3 (per-minor-version builds), no `.pyi` stubs, no `py.typed` (verified absent), version stated twice (`project.version = "0.1.0"` vs `atx::vol::version()`, equality pinned only by a test). `atxvol.report` claims "pure stdlib" but `report.io`/`report.dispersion` import `atxvol`, and any `atxvol.report` import triggers the package `__init__` → `_core` — the reporting layer is unusable without the compiled extension. Docs: one good README; no examples directory, no API reference. Pandas interop: none (dict-of-ndarrays is workable; `date` is `list[str]`, not `datetime64`).

## 4. REPORTING (`atxvol.report`)

**Good:** metrics are folded by the C++ `tearsheet`, never reimplemented (`dispersion.py:84-86`, `io.py` docstring); the closure identity is re-asserted post-round-trip and printed with its residual (`dispersion.py:222-276`); ragged results raise before OOB; every chart ships a table twin; palette is genuinely validated with slot-order-as-mechanism, non-cycling `series_color` with a loud error (`theme.py:56-67`), and both are pinned by tests; charts follow sane rules (zero on P&L axes, diverging bars, facets over dual axes, y=x agreement scatter, no dashed grids). Component/chart test coverage is thoughtful (`test_report.py` guards tick crowding, viewbox containment, escaping, self-containment).

**Defects/risks:** (a) the friction-regime invariant is absent (P1 #4 above) — this is the headline reporting-correctness issue; (b) `build_report_from_run` — the actual pnl_track.html deliverable — has **zero test coverage** (no run-dir fixture; `test_report.py` stops at components/io); (c) `_cum` silently zeroes NaN rows (`dispersion.py:58-63`) — a gap in the track flatlines with no annotation; (d) attribution section mixes two sources — the figure/table sums per-row columns while the totals table uses `sheet.attr_*`; with `record_every_n > 1` they diverge silently, and nothing cross-checks them; (e) `_short` strips the year from date ticks (`dispersion.py:66-67`) — multi-year runs get ambiguous x-axes; x-position is index-spaced so calendar gaps compress; (f) `small_multiple`/`line_chart` IndexError if `values` outruns `x_labels` (P3); (g) `FacetGrid` emits a duplicate `<style>` block per instance; (h) `build_standalone_report.py` is a second, divergent theme (dark-mode aware where `theme.py` is light-only) for a different artifact — fine as a one-off, but two visual systems now coexist. Also note `build_report_from_run` looks for `surface_backtest.tsv`/`backtest.tsv` but not the `pnl_track.tsv` the README's Python pipeline writes — a user following the README then calling the renderer hits a `FileNotFoundError` unless they know the C++ run-dir convention.

## 5. Verdict

This is an unusually disciplined first-cut binding: lifetime hazards (`string_view` archive items, moved-from `CurveSurface`, ragged SoA results) are identified and guarded in comments and code, GIL handling on the long-running paths is correct, defaults match C++, the fold-in-C++/format-in-Python split in the report layer is the right architecture, and the backtest test suite holds the bindings to the engine's own economic invariants including bit-identity under threading. But it is a *consumption* API, not a Vola competitor yet. Top three risks: (1) the friction-regime enforcement the sprint mandated is stranded on an unmerged branch, so main's Python renderer will produce exactly the misleading frictionless report the sprint flagged; (2) the error/exception surface (no `.code`, batch-IV aborts on first bad lane, ts_ns precision loss in round-trip) will burn the first real user with real data; (3) everything performance-differentiating — laned American batch kernels, chain valuation, and all fitting — is unbound, so any Python-side benchmark against Vola's API loses by construction. Top three investments: (1) bind the fit front-end (`OptionChain`/`MarketEnv` → `PricerFitter`/`VolaSession` → `to_priced_surface`) — it completes the lifecycle and is the product's actual pitch; (2) numpy-native batch surfaces for American price/greeks/IV and `PricedSurface` grid queries with NaN+status semantics; (3) merge/port the regime-first reporting contract into `atxvol.report`, add a run-dir fixture test for `build_report_from_run`, and fix the four small io/exception fidelity bugs (ts_ns `int()`, `.code`, lane statuses, kv-header heuristic) — all are afternoon-sized.
