## 1. CORRECTNESS — ranked defects

### P1

**P1-1. `PricedSurfaceView` skips all semantic validation that `PricedSurface::create` enforces; a NaN in the mapped `T` column drives an out-of-bounds read.**
`C:\atx\atx-vol\src\priced_surface_view.cpp:165-347` (`create_over_record`) validates only framing/bounds/alignment — it never checks ascending/finite `T`, positive/finite `forward`, `S > 0`, or finite `r`, all of which `PricedSurface::create` rejects (`C:\atx\atx-vol\src\priced_surface.cpp:381-405`). Because v2 integrity is lazy (payload CRC never checked on the price path, by design), a corrupted record reaches the query path. Concrete failure: craft/corrupt a record so `col_T_[n-1]` is NaN. In `interp_forward` (`priced_surface_view.cpp:365-408`), `T <= firstT` and `T >= lastT` are both false against NaN, so the interior branch runs; `std::upper_bound(col_T_, col_T_+n, T)` returns `col_T_+n` (all `T < NaN` comparisons false), so `hi == n` and `col_T_[hi]`/`col_forward_[hi]`/`col_qeff_[hi]` read **one element past the validated column** — out of the record extent, and out of the backing span when `create_over_record` is called on an exact record span (it is a public API). For in-file records the read lands in tail padding (garbage served silently). Beyond the OOB, the broader defect is asymmetric trust: `reconstruct_v2_record` funnels through `PricedSurface::create` and ParseErrors on this data; the view silently serves it. Fix shape: replicate the create() invariant checks (ascending finite T, positive forwards) in `create_over_record` — O(n) at open, off the hot path.

**P1-2. `AlOpts::n_quad_price` is not persisted by any format — round-trip is not bit-identical for decoupled-premium surfaces.**
`ArchivePricingRecord` (v1), `ArchiveV2SurfaceHeader`, `DbSymbolRecord`, and the view's pricing decode all serialize only `{n_collocation, n_quadrature, max_newton_iter, tol}` (`C:\atx\atx-vol\src\surface_archive.cpp:483-485,1036-1039`; `src\surface_archive_v1.cpp:216-219`; `src\priced_surface_view.cpp:227-230`; `src\surface_db.cpp:263-265`). `AlOpts::n_quad_price` (`C:\atx\atx-vol\include\atx\vol\american.hpp:49-70`) reads back as 0 (tied). A surface fit/priced under the "ql_fast" rung (`n_quadrature=8, n_quad_price=32`) archives, then reprices post-load with premium quadrature 8 — different theo values, violating the header's "round-trips … with IDENTICAL theo values" contract (`surface_archive.hpp:11`). It is acknowledged in a comment ("does not (yet) persist this knob") but contradicts the format's stated guarantee and every bit-identity test (which only exercise tied presets). Any populate-tier adoption of decoupled premium silently changes all backtest marks after archive round-trip.

**P1-3. `col_borrow_off` is unvalidated in the view (validated in reconstruct).**
`create_over_record` checks 7 columns (`priced_surface_view.cpp:193-201`) but omits `col_borrow_off` (and `col_nused_off`/`col_ndropped_off`), then materializes `v.col_borrow_ = reinterpret_cast<const double*>(base + h.col_borrow_off)` at line 217 from the unvalidated offset. `reconstruct_v2_record` validates all 10 (`surface_archive.cpp:1008-1014`). `col_borrow_` is currently never dereferenced by the view — the defect is dormant — but the pointer is live in the object and one refactor (exposing SliceContext from the view, the natural wave-2 step) away from an OOB read from a CRC-unchecked offset. Also constructing an OOB pointer is itself UB. One-line fix: add the three columns to the `column_in_bounds` conjunction.

### P2

**P2-1. No fsync before rename — publish is atomic against crashes of the process, not of the machine.**
`write_surface_archive_v2_file` (`surface_archive.cpp:638-670`), `write_surface_archive_file` (`surface_archive_v1.cpp:692-724`), and `write_manifest_file_atomic` (`surface_db.cpp:769-794`) all do ofstream-write → close → `std::filesystem::rename`, with no `FlushFileBuffers`/fsync of the file (or directory). On power loss after rename but before data flush, the destination can be a correctly-named file with zero/garbage content; the CRC check makes the reader fail cleanly, but the **previous good version was destroyed by the rename** — data loss, not just unavailability. For a store whose manifest rewrite path (`persist_locked`) replaces the only manifest on every mutation, this is the top durability gap.

**P2-2. Rename-based publish is not reliable on Windows under concurrent readers; no retry.**
`std::filesystem::rename` → `MoveFileExW(REPLACE_EXISTING)` fails while any process holds the destination open without `FILE_SHARE_DELETE` — MSVC `std::ifstream` (used by `open_file`, `current_identity`, `read_partition_identity`) and `atx::tsdb::Mapping` (`open_mapped`, held for a whole `MarketSnapshot::load`) both do. A backtest reading a partition while a corpus job republishes it makes the writer fail with IoError (temp cleaned up — safe, but the publish is lost, and none of the three writers retries). On POSIX this same code succeeds. Cross-platform behavioral divergence in the core publish primitive.

**P2-3. Lazy per-record CRC is never verified by any production caller.**
`SurfaceArchiveV2::validate_symbol`/`validate_all` (`surface_archive.cpp:1264-1297`) have zero callers outside tests (verified by grep across src/examples/tools/python). `open` checks only header + lookup‖directory. So the entire data section is unprotected in practice: media bit-rot inside a record flows directly into prices with no detection anywhere in the pipeline (corpus checkpoint verification, `MarketSnapshot::load`, `SurfaceDb::load_surface` — none validates). The lazy-CRC *design* is fine; having no scrub hook at all (e.g., validate-once-per-file-open policy, or a corpus-checkpoint `validate_all`) is an operational gap. Note also: bytes in inter-record padding gaps and the tail pad are covered by **no** CRC at all (harmless — never read — but relevant to a byte-audit).

**P2-4. External truncation of a mapped archive is an unhandled crash.**
`SurfaceArchiveV2::open_mapped` (`surface_archive.cpp:818-836`) + `MarketSnapshot::load` (`src\backtest.cpp:1141-1160`): if another process truncates/replaces-in-place the file while mapped, page access raises `EXCEPTION_IN_PAGE_ERROR` (Windows) / SIGBUS (POSIX) — a crash, not a `Result`. Mitigated on Windows by the sharing-mode lock above (truncation will usually fail), but the failure mode is undefined rather than designed. Standard mmap trade; undocumented in `atxvsa2-format.md`.

**P2-5. `SurfaceArchiveV2::find` returns a fabricated directory entry with zeroed `n_slices` / `kind_bits` / `payload_crc32c`.**
`surface_archive.cpp:864-877` copies only offset/size/hash/uid/symbol from the lookup slot; the doc comment ("Resolve `symbol` … to its directory entry") does not say so (v1's equivalent at least says "fabricated" in the header). A caller passing `find()`'s result to `reconstruct_entry` works (offset/size present), but any caller consuming `payload_crc32c` (the F6 identity ingredient) or `n_slices` gets zeros. API trap.

**P2-6. Corpus checkpoint comment claims `map_all` "touches nothing but framing" — false for heavy kinds.**
`C:\atx\atx-vol\src\corpus.cpp:879-881`: `map_all()` constructs a `PricedSurfaceView` per record, which **eagerly materializes** ConvexDense/SplineVol curves (allocations + node-array copies + spline second-derivative solves, `priced_surface_view.cpp:291-339`) even though the checkpoint only counts surfaces. Correctness of the comment aside, this makes checkpoint resume O(heavy-payload) instead of O(framing) for dense SPY-style dates.

**P2-7. v2 has no lookup↔directory cross-check (v1 does).**
v1's `map_all` verifies `find_directory_slot` + `directory_identity_matches` per entry (`surface_archive_v1.cpp:1183-1186`) and rejects cross-linked records (tested: `MapAll_RejectsCrossLinkedDirectoryAndLookupRecords`). v2's `open_impl` validates directory entries (bounds, alignment, ≥ data_offset) but validates **nothing about occupied lookup slots' offsets/sizes** (`surface_archive.cpp:755-759` checks only `symbol_len`), and never checks slot↔directory agreement. A slot pointing at the wrong (valid) record serves the wrong symbol's surface with no error. Memory safety is preserved (`map_symbol` bounds-checks; the view's base-alignment check at `priced_surface_view.cpp:175` catches misaligned slots; record magic rejects metadata aliasing) — this is a serve-wrong-data integrity gap under metadata corruption that passes the metadata CRC (i.e., a buggy writer or deliberate tamper).

**P2-8. Strict-aliasing / object-lifetime pedantry in the zero-copy columns.**
`priced_surface_view.cpp:210-219,457-458` `reinterpret_cast`s mapped `std::byte` storage to `const double*/uint32_t*/uint64_t*` and indexes it. No `double` objects were ever created in that storage (file bytes / vector<byte>), so this is formally UB (C++20; `std::start_lifetime_as` is the C++23 cure). All alignment preconditions are enforced, and MSVC/clang-cl compile it as intended — practical risk ≈ 0 on this toolchain, but it is the one place the codebase's "no UB" convention is knowingly bent; worth an in-code note or a memcpy-based accessor for the two bracket loops (measurable cost ~0).

### P3

- **v1/v2 asymmetry on LinearVariance node floor**: v1 reconstruct requires `node_count >= 2` (`surface_archive_v1.cpp:1083`); v2 reconstruct and the view accept `nc == 1` (`surface_archive.cpp:1096`, `priced_surface_view.cpp:286`). Eval is safe at nc==1 (both clamp branches cover), but the two readers disagree on validity.
- **`schema_hash` folds only `sizeof`** (`surface_archive.cpp:170-184`): a same-size field reorder hashes identically. In-tree the `offsetof` static_asserts (`surface_archive.hpp:583-613`) pin it at compile time; a divergent fork writing same-size/different-layout files would pass the hash. Acceptable, but the hash is weaker than the doc implies.
- **v2 minor version is dead**: reader checks only `major` (`surface_archive.cpp:684`); the SplineVol layout change was versioned by salt bump, not minor. Minor exists on disk but gates nothing.
- **`want_slots` u32 truncation** (`surface_archive.cpp:390-392`): with ~43M+ items × 100 / load_pct the intermediate exceeds u32 before `next_pow2` cast; failure mode is a clean "lookup table full" Internal error, not corruption. Theoretical.
- **`ArchiveV2DirEntry.n_slices` (u16) never cross-checked against `ArchiveV2SurfaceHeader.n_slices` (u32)** — v1 checks the analogous pair (`surface_archive_v1.cpp:985`).

### Verdicts on specifically-tasked areas

- **Truncated files / huge allocations**: strong. Both openers enforce `file_size == bytes.size()`; every count-driven allocation (`lookup_slot_count`, `surface_count`, node counts) is bounded by prior byte-bounds checks against the actual file size, so a small malicious file cannot induce a large allocation. All record parsing is memcpy-based and bounds-checked; the only OOB found is P1-1.
- **Endianness / portability**: explicit `endian=1` + `pointer_bits=64` stamped and rejected on mismatch; little-endian-LP64-only is documented in both header and format doc. Consistent.
- **Concurrent read safety**: v2 archive is immutable after open (parsed copies + const span) — const queries are safe; views are immutable; `LoadedSurface` co-owns the mapping so SurfaceDb LRU eviction can never dangle a held view (tested: `ViewCacheEvictedViewStaysValidWhenHeld`). SnapshotCache's mutex + shared_future coalescing + generation-guarded `release_active_load` + exception-path release (`snapshot_cache.cpp:321-344`) is correct; `trim` correctly refuses to evict in-flight entries.
- **TOCTOU stat→read**: `current_identity`/`read_partition_identity` header-read happens before the full open; a rewrite in the window stores a self-consistent identity from the actually-opened bytes (`cached_partition`, `surface_db.cpp:1197-1217`), so staleness converges on the next call. Benign one-call windows only.
- **v1→v2 migration fidelity** (`C:\atx\atx-vol\tools\migrate_atxvsa_v1_to_v2.cpp`): reconstruct-through-v1 → re-serialize-through-v2 preserves every fitted double, SliceContext, ConvexDense diagnostics, uid, provenance (legacy zero-fill correctly kept nullopt so it round-trips as legacy). Loses: v1 `created_ts_ns` (re-stamped) and, transitively, `n_quad_price` (P1-2, equal on both sides so migration itself is faithful). Sound.

### Content-derived `created_ts_ns` (commit 66de2ae, branch-only) — soundness

The 0-sentinel now fills from `(CRC32C(bytes[header_size, EOF)) << 32) ^ file_size`, clamped away from 0; explicit nonzero stamps honored verbatim; header excluded from its own hash (no self-reference). Assessment:

- **Reproducibility goal: sound.** Identical builds → identical bytes → identical container; previously the wall clock forced a spurious SnapshotCache evict+reload on every rebuild of identical content — this is a behavioral improvement, not just cosmetics.
- **Staleness goal: sound with quantified caveat.** The derived stamp adds only 32 bits of content entropy, but `ArchiveContentIdentity` = {file_size, created_ts_ns, header_crc32c, metadata_crc32c}, and metadata_crc32c already covers the per-record CRC mirrors in the directory. An undetected in-place rewrite requires simultaneous preservation of file_size + content CRC32C + metadata CRC32C + header CRC32C — ~2⁻⁶⁴ for random change; trivially forgeable adversarially (CRC is linear), which is fine for the local cache-staleness threat model but must never be relied on as tamper evidence. Interaction with `evict_if_stale` (`snapshot_cache.cpp:145-156`) and `cached_partition` is correct: same content → hit (now correct), different content → evict.
- **Semantic loss, undocumented.** `created_ts_ns` is no longer a timestamp: bit 63 can be set (negative as int64), ordering by it is meaningless. On main nothing orders archives by it (`run_report.cpp` prints the *manifest's* `DbPartitionInfo.created_ts_ns`, which stays wall-clock via `surface_db.cpp:1115`), but the field name, `surface_archive.hpp:336` ("fill from the system clock"), and `atxvsa2-format.md` were not updated — doc drift that will bite the next consumer treating it as time. A pad-gap-only byte change now changes identity via the stamp (previously invisible) — harmless, slightly stronger.
- Net: **approve the mechanism; require doc/comment updates and note the 32-bit caveat.** The 29150 observation ("cannot be pinned to constant") is correctly honored.

## 2. PERFORMANCE

- **Landed wins are real**: v2 kills the whole-blob CRC per open, the 4 KB/surface pad, and per-slice allocation for parametric kinds; `open_mapped` + `reconstruct_entry` in `MarketSnapshot::load` gives the subset load without whole-file reads or double hash probes (snapshot_load 1008→44 ms per the sprint).
- **Biggest remaining gap: the zero-copy view is unwired on the hot path.** `PortfolioPricer::SurfaceSet` still takes `const PricedSurface*`, so `MarketSnapshot::load` pays owned reconstruction (make_unique per slice + `with_query_pricing` re-preparation) for every referenced surface every date (`backtest.cpp:1176-1179`, documented seam §6). `SurfaceDb::map_surface`/`LoadedSurface` — the flagship reconstruct-free path — has **zero product callers** (python binds only `load_surface`).
- **`SurfaceDb` still reads whole partition files into heap**: `open_partition` and `cached_partition` use `open_file`, not `open_mapped` (`surface_db.cpp:1149,1198`), pinning up to 16 full partitions of bytes in RSS (the LRU comment at `surface_db.hpp:348-360` says exactly this is deferred). The mmap seam exists one call away.
- **Write amplification is structural**: single-surface update = full-partition re-serialize + rename; every `upsert_symbol` re-decodes, re-encodes, re-sorts, re-parses (defensive double-parse in `persist_locked`), and rewrites the **entire** manifest. `populate_surface_db` upserts per symbol in a loop (`surface_db_populate.cpp:525`) → O(S²) record traffic; fine at MAG7 scale, measurable at the 1030-name universe target.
- **`find_slot` allocates**: `canonicalize_symbol` returns a `std::string` per probe (`surface_archive.cpp:842`) — a heap alloc on the O(1) lookup path; a stack `array<char,32>` version would zero it. (`reconstruct_entry` was added precisely to dodge this; the primitive itself still pays it.)
- **Symbol index**: open-addressed, pow2, ≤70% load, linear probing over 64-B slots — appropriate; O(1) with good constants. Directory binary layout is sorted, enabling future range scans (unused).
- **Heavy-kind materialization at view construction** (ConvexDense/SplineVol) is the documented wave-2 residual (`atxvsa2-format.md` §4); it also taxes count-only consumers (P2-6).
- **Compression: none** (see §3) — node-array-heavy ConvexDense partitions are stored as raw f64; on a corpus of daily SPY surfaces this is the dominant on-disk cost and read-bandwidth term once mmap removes the CPU cost.

## 3. FEATURE GAPS vs a production surface store

**Documented-deferred** (no action needed beyond tracking):
- Real mmap inside `SurfaceDb` (`surface_db.hpp:348-353`); pricer-on-views cutover (seam §6, `surface_archive.hpp:702-713`); full zero-copy ConvexDense/SplineVol (spline `m2nd[]` in-record — `atxvsa2-format.md` §4); v1 deletion (S4 wave 2); curve-set/profile/correction-cache side blobs (README "Archive side-blobs"); `AlOpts::n_quad_price` persistence (`american.hpp:66-68` — but see P1-2: the deferral contradicts the bit-identity contract, so it is *mis*-documented).

**Silently missing** (no doc acknowledges the absence):
- **Compression** — none, at any granularity; not listed as a non-goal in `atxvsa2-format.md` despite the doc's careful design-lineage section (Arrow/Feather, its cited lineage, has buffer compression). Even fast LZ4-per-record would be format-visible and needs deciding before the format ossifies.
- **Point-in-time / as-of query** — partitions are date-keyed by *convention* (corpus writes `<date>.atxvsa`); there is no "surface for symbol X as of ≤ t" API; callers hand-assemble date keys.
- **Append / streaming / incremental update** — every format is write-once whole-file; a one-surface refresh rewrites the partition. No tick-level or intraday update story.
- **Partial reads below symbol granularity** — `map_symbol` is the floor; no per-expiry/slice access (the columnar layout would support it).
- **Integrity beyond CRC32C** — no strong hash, no signature, no scrub scheduling (P2-3). CRC32C is corruption detection, not authenticity.
- **Retention / compaction / GC** — `drop_partition` exists; nothing age-based; orphaned `.atxvsa` files after crash-in-drop are acknowledged garbage with no sweeper.
- **Schema evolution** — the only mechanism is salt-bump-reject-everything (used for the SplineVol fix); additive kinds are supported (new kind byte), additive *fields* are not. A production store needs a versioned-decode story or an explicit "rebuild the world per schema change" policy statement.
- **Catalog** — manifest lists {key, count, file_size, ts}; there is no symbol→partitions inverted index (finding which partitions contain symbol X means opening every partition), and `run_report`'s CSV is the only cross-partition metadata view.

**Test coverage judgment**: v1's adversarial suite is excellent (17+ "repaired blob" corruption tests: bounds, alignment, uid/symbol/kind-bit mismatches, cross-linked records, concurrency). v2's is materially thinner: bit-identity per kind, subset isolation, one record-corruption-via-validate test, one header-corruption test, cross-format rejection — but **no** tests for corrupt lookup slots via `map_symbol`, non-ascending/NaN columns through the view (P1-1 would be caught by exactly such a test), payload-overlapping-columns, unknown kind byte through `map_all`, `open_mapped` directly (no test references it), or rewrite-while-mapped. `SurfaceDb` cache tests are good (eviction, identity-rewrite, held-view survival). Recommend porting the v1 "repaired" corpus of adversarial tests to v2 before v1 (and its suite) is deleted — otherwise the deletion removes most of the format-hardening regression net.

## 5. State of the union

This layer is unusually disciplined for its age: fixed-width POD wire structs pinned by static_assert + offsetof, layered CRC with an honest write-up of what the lazy-CRC trade costs, memcpy-only parsing with per-field bounds checks that make small-file/huge-alloc attacks structurally impossible, a genuinely clean v1→v2 break with a quarantined legacy TU and a faithful migrator, and correct shared-ownership lifetime design (`LoadedSurface` co-owning the mapping) that makes the mmap seam safe by construction. The top three risks: (1) **the zero-copy view trusts data the owned reconstruct would reject** — with CRC deliberately lazy, the view is the de-facto untrusted-input parser and currently lacks the semantic validation (P1-1) and one column bound (P1-3) to be one; (2) **the round-trip contract is quietly false for `n_quad_price`** (P1-2) — a pricing-correctness time bomb armed the day a populate tier adopts decoupled premium quadrature; (3) **durability/publish semantics on Windows** — no fsync-before-rename plus rename-fails-under-reader means the store's atomicity story holds for process crashes only, and republish can spuriously fail in exactly the concurrent backtest-plus-rebuild workflows the sprint is building toward. Top three next investments: harden `create_over_record` to reconstruct-equivalent validation and port the v1 adversarial test corpus to v2 before deleting v1; persist `n_quad_price` (one reserved u16 exists in both surface headers — a salt bump away); and finish the wiring the format was built for — `SurfaceDb` on `open_mapped`, `PortfolioPricer` on views, and one scheduled `validate_all` scrub point — since today the store's best code paths (subset zero-copy, lazy-validate) are mostly built but not yet load-bearing.
