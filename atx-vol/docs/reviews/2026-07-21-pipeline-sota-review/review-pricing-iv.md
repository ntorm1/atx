## 1. CORRECTNESS — ranked defects (fresh findings)

**C1 — P2 — Correction-cache out-of-box clamp silently serves wrong marks on the live-session path (σ > 1.5, T < T_min).**
`session.cpp:666-670` fixes the cache box at `σ ∈ [0.05, 1.5]`, `T ∈ [0.9·T_lo, 1.1·T_hi]` (tight mode). `CorrectionCache::eval` clamps out-of-box coordinates to the edge (`correction.cpp:658-660`) and the legacy `VolaSession` serve path (`fair_value`/`greeks`/`evaluate_ladder` → `american_price_cached*`) never consults `contains()` — only the archived `PricedSurface` path has the certified-box `ColdFallback` route (`query_pricing.hpp:40-45`). Consequences: (a) any board whose fitted σ exceeds 1.5 (earnings names, memes, 0DTE panic — σ 1.6–3 is routine) gets its entire correction served at σ=1.5, and the correction's σ-partial is zeroed out-of-box (`eval_value_and_dsigma`, `correction.cpp:868,883`) so cached IV inversion silently degrades toward the European vega map; (b) queries below `T_min` (projection/backtest date-shift, intraday decay of the front expiry after the session snapshot) serve the `T_min`-edge correction — an **overstated** early-exercise premium the A2 intrinsic floor cannot catch (it only fixes the under-intrinsic direction). Failure scenario: `fair_value(K, T=2d)` on a session built when the front expiry was 5d prints euro + corr(5d·0.9) — a stale, too-large EEP; no error, no route flag. Fix direction: gate the session serve path on `contains()` with cold fallback (the PricedSurface pattern already exists), or widen σ_max adaptively from the fitted board.

**C2 — P2 — Reproducibility contract relaxed by Auto-ON AVX2 marks; documentation and comments now self-contradictory.**
`kShipAvx2Boundary = true` and `kShipAvx2Greeks = true` under `Auto` (`american_boundary_batch.cpp:83,153`, USER OVERRIDE documented at `:75-82`). Default marks on the portfolio path are now AVX2-host-dependent at ~1e-13 (economically nil; thread-count invariance is properly closed by the tile schedule gated on the *same* predicate, `portfolio_pricer.cpp:819-829,1425-1428`). But: (a) the function-comment at `american_boundary_batch.cpp:88` still says "Auto => scalar, the bit-reproducible default" — directly contradicts the code beneath it; (b) `american_batch.cpp:307-309` still calls the greeks route "dark in production until the PM flips it"; (c) README (`:328-331`) still claims "batch == scalar holds bit-for-bit" and "SIMD/AVX2 … does not help here … both reverted". A future maintainer reading any of these will mis-model the shipped default. The cross-host divergence itself is an accepted, documented risk — but it needs a single authoritative statement, and a non-AVX2 CI leg to keep the scalar patch-paths honest (currently no such gate; `isa_golden_tol.hpp` handles FMA build-flag drift, not runtime-host route divergence of one binary).

**C3 — P2 — Legacy `bulk_price` cached routes: no intrinsic floor and inconsistent gamma units.**
`bulk.cpp:171-177` (PriceOnly) and `:215` (AmericanFirstOrder) serve raw `euro + F·corr` with **no intrinsic/euro floor** — the exact A2 defect, fixed everywhere else, still live on this public API (acknowledged in-code `:165-167` but the API is not deprecated). Worse, in `AmericanFirstOrder`: the `use_corr` branch leaves `out.gamma` as the raw **forward-space** B76 gamma with no correction term and no m² spot conversion (`bulk.cpp:203` init, never updated in the corr branch), while the no-corr branch converts to **spot** gamma (`:221`); vanna/charm are raw forward-space both ways while delta is spot (`:227`). Failure scenario: a caller aggregating bulk gamma across cached and uncached lanes mixes units differing by m² ≈ 1 + 2(r−q)T (up to % level at LEAP tenors) and misses the (d2c/dk2−dc/dk)/F correction entirely. Fix: either route bulk through `american_greeks_first_order` (which does all of this correctly, `american.cpp:1849-1908`) or retire the API.

**C4 — P3 — σ→0 degenerate guard returns spot intrinsic ahead of regime classification.**
`andersen_lake_core` (`american.cpp:1786-1789`), `AloPricer::price` (`:2027-2031`), and both slices short-circuit `σ ≤ 1e-8 → max(K−S,0)`. For carry-dominant European-regime cases (e.g. put r=0, q=5%, T=1: correct σ→0 limit is df·(K−F)⁺ = 4.88 on S=K=100) this is discontinuous at the guard: σ=1.1e-8 returns ~4.88 (B76 European branch), σ=0.9e-8 returns 0. Unreachable through the IV stack (kIvMin=0.005 floor) but a genuine limit defect for direct `american_price` callers and any future σ-continuation logic. Fix: classify regime first; degenerate σ should collapse to the *European* σ→0 limit (df·forward-intrinsic) with the American≥intrinsic floor.

**C5 — P3 — Cached IV Newton derivative inconsistent with the served (floored) forward map.**
`american_price_and_vega_cached` floors the price at intrinsic (`american.cpp:2566`) but the returned vega is that of the *unfloored* map (B76 vega + F·∂c/∂σ, only the corr-clamp gate applied `:2549-2553`). Where the floor binds (deep-ITM quotes just above intrinsic) the true served-map derivative is 0; Newton takes steps against a non-zero vega into a flat residual. rtsafe bracket keeps the answer correct, only iterations are wasted; but the same inconsistency means near-floor cached IVs converge by bisection at the tolerance edge. Cosmetic-to-minor.

## 3. FEATURE GAPS vs Vola-class

- **Discrete cash-dividend American pricer: still the #1 modeling gap.** Escrowed/q_eff folding is self-consistent for fit-and-refit (error absorbed into de-Am IVs) but misprices the *exercise decision* around ex-dates: deep-ITM calls immediately pre-ex-date and short-dated ITM puts spanning an ex-date carry O(div − remaining-time-value) errors, and the McDonald-Schroder swap used everywhere is only exact under continuous carry. For SPY-class divs (~0.3%/qtr) this is bp-level; for high-yield single names and LEAPs it is many cents and corrupts `assignment_risk` (whose call carry-benefit `q·S·T`, `american.cpp:3430`, linearizes what is really a discrete-date decision). The `DISCRETE_DIV_FD_CACHE` route slot was removed; the CN PDE oracle exists in tests (`tests/support/oracle_pde_golden.*`) and is the natural seed for a production `AmericanMethod::DiscreteDivPde` tier. ## 5. Verdict

The numerical core is in the best shape it has been: the one genuine math error (BAW derivative sign) is fixed with convergence contracts and AVX2 bit-parity maintained, the cached hot path is now floored, fused (1 Clenshaw/Newton-step), T-collapsed, warm-chained and audit-batched, the ISA/global-state and portfolio-lifecycle races from the prior reviews are structurally fixed, and the SIMD investment finally reaches a production path with a defensible determinism story (tile-scheduled, same-predicate gating). The top three risks are (1) **silent correction-cache extrapolation on the live-session serve path** — the σ≤1.5 / T-box clamp serves wrong marks with no route flag for exactly the high-vol, short-dated boards where a market maker is most exposed (C1); (2) **the reproducibility contract is now ambiguous** — Auto-ON AVX2 marks with stale "bit-reproducible-by-default" comments/README and no non-AVX2 CI leg means cross-host drift will be discovered by a consumer, not a test (C2); (3) **the discrete-dividend modeling gap**, which bounds achievable accuracy on high-div single names and quietly degrades assignment-risk and pre-ex-date ITM-call marks regardless of how good the continuous-carry engine gets. The top three investments, in order: gate the session serve path on `contains()` with cold fallback + adaptive σ_max (small, closes the worst silent-wrongness cliff); a discrete-div pricing tier grown from the existing CN PDE oracle behind `AmericanMethod` (the Vola-parity differentiator); and the remaining cheap throughput structure — pack the σ-node/cache-row boundary solves through the already-shipped 4-lane solver plus F6's barycentric hoist — which together are the credible route from 21k toward the top of the 20–33k inv/s/core band without new numerics.
