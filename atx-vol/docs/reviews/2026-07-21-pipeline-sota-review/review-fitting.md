## 1. CORRECTNESS — ranked defects

**C-1 (P1) — Quasi-explicit SVI Nelder–Mead returns box-inconsistent parameters; final mapping can divide by a negative/near-zero σ.**
`src/svi_calib.cpp:316-331` (`nm_eval` clamps (m, σ) **by value**), `:335-434` (`nm_search` stores the **raw, unclamped** proposal in the vertex while recording the SSE evaluated at the clamped point; `:430-433` writes the raw best vertex back), `:884-892` (`b_fit = c_raw / sigma_cur`, `rho_fit = d_raw / c_raw`).
Failure scenario: any smile whose optimum saturates a bound (σ→σ_min = 1e-3 on a short-dated kinked smile). Reflection/expansion steps drive the vertex σ negative; its recorded f corresponds to σ = 1e-3, so the negative-σ vertex can win. The final (a,b,ρ,m,σ) then pairs the clamped-point linear solution with an out-of-box σ: `b_fit` flips sign or blows up (σ ≈ 1e-3 ⇒ b up to 10³·c_raw). Downstream, `arb_check_butterfly_svi_mm` catches b ≤ 0 and `svi_project_mm` resets b to 1e-8 — the canonical `VolCurveKind::Svi` route (IlliquidSmallCap / HtbDividendName / VolProduct profiles) then **serves a near-flat slice with a success status**. Fix: clamp the winning vertex into the box before the (u,v)→(a,b,ρ) map (or store clamped coordinates in the simplex). No test pins this.

**C-2 (P1) — SVI butterfly "admissibility" is necessary-conditions-only; the FD backstop only scans |k| ≤ 0.6, so a served raw-SVI slice can carry wing butterfly arbitrage.**
`src/arb.cpp:458-514` (`arb_check_butterfly_svi_mm` checks exactly: b>0, σ>0, |ρ|<1, w_min ≥ 0, b(1+|ρ|) ≤ 4/T). These are **not sufficient** for Durrleman g(k) ≥ 0 — the canonical Vogt counterexample (a=−0.041, b=0.1331, ρ=0.306, m=0.3586, σ=0.4153, T=1) passes all five while butterfly-arbitrageable. The only density check on the served path is `validate_parametric_risk_shape` (`src/vol_curve.cpp:23-37`), which scans **k ∈ [−0.60, 0.60]** (256 pts). A QE fit whose g<0 region sits at |k| > 0.6 is admitted as a "risk shape"-validated slice. Same 5-condition set drives the selector disqualification (`src/curve_selector.cpp:72-97`) and both SVI surface-driver gates (`src/svi_calib.cpp:1428-1435`, `:1522-1529`). The band-limited scan is a deliberate "tradeable risk band" policy for calendar, but for **strike density on a parametric curve with closed-form wings** there is no cost excuse for not scanning the full quoted range (as C8 and CStar already do: obs range ± 0.5, `src/vol_curve.cpp:542-548`, `src/cstar_calib.cpp:674-683`).

**C-3 (P2, wrong-number at T extremes) — Two mutually inconsistent "Lee bound" conventions, both off the true bound.**
(a) `src/essvi_calib.cpp:362-392` `lee_project` enforces θφ(1+|ρ|) ≤ **4/T** with θ = *total* variance, and `CalibOpts::lee_bound_project{true}` by default (`include/atx/vol/calib.hpp:244`). The true Lee/Gatheral wing constraint in total variance is θφ(1+|ρ|) ≤ 4 (T-free) — already enforced by the Mingone cube (`essvi_phi_max`, `src/vol_surface.cpp:163-175`). So the projection is a no-op for T < 1 and **over-tight for T > 1**: a 2-y LEAP on a high-vol steep-skew name (σ≈0.5, φ≈4, |ρ|≈0.8 ⇒ θφ(1+|ρ|)≈2.9 > 4/T=2) gets its wings silently flattened below market. The comment ("Lee's tighter short-dated bound") describes the opposite of what the code does.
(b) `src/svi_calib.cpp:470-480` `mm_project_admissible` uses b(1+|ρ|) ≤ 4/T with w = total variance; for short T this admits total-variance wing slopes ≫ 2 (T=1wk ⇒ bound ≈ 200), i.e. moment-exploding wings pass the "Lee" gate; the density backstop is C-2's band-limited scan.

**C-4 (P2) — `arb_project_calendar_essvi_total`'s "constant-shift trick" requires a partition-of-unity basis; the C2 bump basis is not one.**
`src/arb.cpp:797-827` adds `c_shift` to every `resid_coef[j]`, asserting the basis is a partition of unity; `detail/resid_basis.hpp:43-56` gives Σ_j B_j(y) ≈ 1.17–1.41 varying with y — the "uniform" lift is a rippled over-lift (up to +41%, with curvature that can locally re-dent g(k)). Currently **dead code** (no production caller — see §4), so latent; the pass-loop remeasure would converge the calendar deficit but the ripple is never density-rechecked.

**C-5 (P2) — `svi_jw_to_raw` symmetric branch accepts σ = 0.**
`src/svi_calib.cpp:1262-1271`: for β ≈ 0 (symmetric smile) and v == v_min, `sigma = (v−v_min)T/(…+1e-18)` = 0 is returned `Ok` (the asymmetric branch rejects σ ≤ 0 at `:1288-1290`). A σ=0 slice has a total-variance kink at k=m (infinite density). Reachable through C8/JW seed paths where v_min==v seeds occur (the exact degenerate seed `c8_calib.cpp:190-210` documents for its own domain).

**C-6 (P2) — Legacy-vs-configured builder inconsistencies in the row weight/noise fields.**
`src/prepared_fitting.cpp:523` sets `noise_sigma = 0.0` when vega ≤ 0 (the configured builder uses 1.0, `src/calib.cpp:198`). In the C8 branch of `fit_slice_curve` (`src/vol_curve.cpp:514-515`) `spread_w = max(2σT·max(noise_σ,1e-7), 1e-9)` — a vega-underflow row (φ(d1) → 0 on an absurd wing) gets sd ≈ 1e-7·2σT, i.e. ~10⁴× smaller than a normal row's, hence ~10⁸× the LM weight: one dead wing quote can own the C8 objective. Edge case (needs vega == 0.0 exactly), but the two builders disagree on a field the fit consumes.

**C-7 (P2) — SplineVol butterfly is diagnostic-only on the pinned-curve path.**
`src/spline_curve.cpp:165-218` (comment: "never rejects or projects"), and the `SplineVol` branch of `fit_slice_curve` (`src/vol_curve.cpp:574-589`) does **not** call `validate_parametric_risk_shape` and has no butterfly gate — only calendar projection. The selector disqualifies violating spline candidates (`curve_selector.cpp:88-94`), but a caller-**pinned** SplineVol curve bypasses the selector, so a butterfly-violating spline slice is served counted-but-unblocked.

**C-8 (P2) — Canonical eSSVI still fits a filter-free observation population.**
`src/surface_parity.cpp:311-313` hardcodes `PreparedObservationPolicy::LegacyEssviCompatibility` (ignores `in.fit_prep_policy`); `prepare_legacy` (`src/prepared_fitting.cpp:423-495`) applies only `strike>0` + `quote_valid` — none of the CalibOpts cascade (kill-mask flags, `max_spread_vol`, `max_spread_to_mid_pct`, `min_vega_weight`, anchors, `max_obs_per_slice`). Stale/wide/flagged quotes therefore still enter the *default-family* production fit (`VolaSession::build` routes Essvi through `run_surface_parity`, `src/session.cpp:1113-1274`), while every other family gets the configured cascade. Mitigated vs the prior review by the opt-in `audit_fit_inversions` reprice-audit and the de-Am strike cap, but the family-dependent filter policy persists.

## 2. PERFORMANCE

- **The canonical eSSVI path is still serial across expiries.** `run_surface_parity` walks chains in one loop (`src/surface_parity.cpp:298`); no `parallel_for`/`run_bounded_fit_tasks` anywhere in that file, while the generic driver fans the identical dominant cost (carry solve + de-Am) across `fit_workers` with size-ordered dynamic scheduling (`src/curve_fit.cpp:368-483`). The de-Am shared-boundary batch (`prepare_legacy` → `shared_boundary_deam_batch`) cuts per-slice cost, but the 2.5× multi-core win the generic path measured is unavailable to the default family.
- **Selector redundancy.** Each candidate refits every sampled expiry from scratch (`src/curve_selector.cpp:528-535`); the C8 candidate additionally runs a full `essvi_fit_slice` per expiry as its seed (`src/vol_curve.cpp:492`) — so evaluating {Essvi, C8} fits eSSVI twice per expiry. Holdout scoring does one **cold `american_price` per holdout row** (`curve_selector.cpp:559-561`) instead of the per-side σ-boundary batch that `audit_european_equiv_iv_batch` already implements (`src/deamer.cpp:152-229`) — O(rows) cold AL solves that could be O(n_σ) per side.
- **Dynamic Eigen allocation inside the LM inner loops.** eSSVI `lm_step` constructs `MatX(3,3)`/`VecX(3)` per damping trial (`src/essvi_calib.cpp:313-327`); SVI-MM's `solve_spd_dense` builds `MatX(5,5)` per call (`src/svi_calib.cpp:67-85`). CStar fixed this exact pattern with stack-capacity matrices (`src/cstar_calib.cpp:52-58`) — the fix was not propagated to the hotter eSSVI/SVI paths.
- **Per-expiry full-chain snapshots.** `ChainPrepass` copies 5 full SoA vectors per usable expiry plus a second copy of the fit rows for certification (`src/curve_fit.cpp:355-361`, `:869-881`, deliberately copied for the profile summary) — measurable allocation churn on 35-slice boards.
- **Repair loops are bounded but heavy.** Calendar projections re-grid ×4 up to 65 536 points over 6 passes (`src/arb.cpp:676-702, 725-765`); `fit_dense_residual`'s greedy arb projection can run 80 × 81-point g-scans with 3 `essvi_total_w` per point (~20 k evals/slice worst case, only when the residual layer is on — off by default).
- **Good reuse already in place** (credit where due): `FitScratch` per-worker arenas with zero steady-state allocation (`essvi_calib.cpp:684-714`); hoisted k-buffers + fused SIMD w/grad batch in the eSSVI objective; QE basis recomputed once per (m,σ) across ≤7 active-set passes (`svi_calib.cpp:129-136, 244-249`); carry solve warm-chains borrow/vols across pairs and legs (`deamer.cpp:566-591`); Illinois-accelerated shared lanes (5.19 vs 22.5 evals/lane, `calib.cpp:737-825`); C8 normal-equation carry-forward (`c8_calib.cpp:216-243`); P-core pinning of outer fit workers (`fit_scheduler.cpp`).
- **Benchmark gating**: `bench/fitting_throughput_bench.cpp` still times `essvi_calib_surface` — a driver that (per §4) no production path calls — so the canonical `OptionChain → PricerFitter` fit remains un-gated (prior F-10; I did not find evidence the baseline was regenerated).

## 6. State-of-union verdict

The stage has moved decisively since the July-11 review: the two worst structural risks — silent partial-fit admission and the unverifiable QP — are genuinely closed (structured per-expiry outcomes, a real admission oracle feeding the fallback ladder, KKT-certified dense solves, transactional `refit_expiry`), the de-Am/carry layer is now the strongest part of the pipeline (winsorized multi-pair robust borrow with confidence gating and term-structure fallback, tolerance-ladder `static_assert`s, batched σ-boundary audits, Illinois-accelerated shared lanes), and determinism/exception-safety claims hold everywhere I traced. The top three remaining risks are: (1) the **default family (eSSVI) still fits a legacy, filter-free quote population on a serial path**, so profile/calib policy and latency remain family-dependent in exactly the way the facade denies; (2) **butterfly admission is weaker than advertised for SVI and SplineVol** — a necessary-conditions polytope plus a |k|≤0.6 scan is not "arb-free by construction", and the unclamped Nelder–Mead vertex (C-1) can hand that weak gate a garbage slice to launder into a flat one; (3) **performance and its gating lag the architecture** — the selector and parity scoring pay cold per-row American solves the codebase already knows how to batch, the LM inner loops still heap-allocate 3×3s, and the checked-in benchmark measures a driver nothing calls. The top three investments, in order: route canonical eSSVI through Configured preparation + the parallel prepass (finishing F-01 rather than re-documenting it); make strike-density admission sufficient (full Martini–Mingone closed form or full-range grid for SVI, a hard gate for pinned SplineVol, and the NM clamp fix); then re-point the fitting benchmark at `PricerFitter::fit` with per-phase counters so the next optimization round is gated on the pipeline users actually run.
