# ATX research workstation

`atx-front` is a React/TypeScript Dockview workstation and a stateless Fastify browser gateway to the native `atx-server` gRPC service. The gateway owns no job, scheduler, cache, or research state. Results and provenance come from the native service; unavailable observations remain unavailable, and synthetic results carry explicit demo labels.

From this directory, run `npm ci`, `npm run build`, then `npm start`. Open `http://127.0.0.1:3000`. Development uses `npm run dev` on port 5173 alongside `npm run gateway`; Vite proxies `/api` to port 3000. The root launch script builds and starts the full stack.

Tabs can be dragged into other tab bars or docked along a panel edge to split the workspace. Dividers resize the groups. **Maximize active panel** enlarges the current pane; **Restore docking layout** returns to its groups. Local storage retains the working geometry, including legacy layouts; **Reset layout** restores the current template grid (Research for a named workspace). **Windows** reopens closed panels. Narrow screens use a compact layout; screens below 850px retain horizontal scrolling to keep dense tables usable.

## Named workspaces

The compact **Workspace** selector separates local Research, Database and Operations templates from server records. Database puts the actual database viewer in the large central pane. Templates are starting points: use **Save as…** to create a durable named workspace. **Save**, **Duplicate…**, **Rename…** and **Delete…** operate on native SQLite records through the provider-neutral gateway; other browsers and server restarts retain those records.

A version 1 workspace document contains its Dockview layout, editable research draft, selected job ID, database source/table/query/page/filter context, experiment composer and recurring workflow composer. Results are fetched from the backend after loading; saved queries are restored without automatic execution. Documents are bounded to 96 KiB and never contain browser authentication credentials. Names contain up to 80 Unicode characters, descriptions up to 512 UTF-8 bytes. Up to 256 workspaces are listed in pages of 100.

Edits display **Unsaved**. Switching offers **Save and switch**, **Discard and switch** or **Keep editing**. Saves and deletes use exact string revision numbers. A conflicting save preserves the working state and offers **Reload latest** or **Save as copy**. Edits made during a slow save remain unsaved; edits made while loading prevent that response from replacing the working workspace. Renaming changes saved metadata and preserves the unsaved draft; deleting leaves an unsaved working copy. Bookmark `/?workspace=<id>`; `?panel=database` can also open that panel while retaining the named layout.

REST routes are `GET/POST /api/workspaces` and `GET/PUT/DELETE /api/workspaces/:id`. Browser write bodies use an object `document`; update/delete require decimal-string `expected_revision`. The gateway translates to the native document JSON and keeps compare-and-swap conflicts as HTTP 409.

The editable request and configuration are a draft for the next submission. Selecting history loads that run's results without replacing the draft; the summary identifies the selected run ID and status. A fresh page initially selects the latest successful run when available.

## Configuration

| Environment variable    | Default / purpose                                                                                                         |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `ATX_WEB_HOST`          | `127.0.0.1`; non-loopback binding requires `ATX_WEB_TOKEN`                                                                |
| `ATX_WEB_PORT`          | `3000`                                                                                                                    |
| `ATX_WEB_ALLOWED_HOSTS` | Additional comma-separated public hostnames, without ports; localhost and the configured bind host are allowed by default |
| `ATX_WEB_TOKEN`         | Optional workstation bearer token; enter it using **Access**                                                              |
| `ATX_GRPC_ADDRESS`      | `127.0.0.1:50051`                                                                                                         |
| `ATX_SERVER_TOKEN`      | Native gRPC bearer token, retained on the gateway                                                                         |
| `ATX_GRPC_TLS`          | Set to `1` to use native TLS                                                                                              |
| `ATX_GRPC_CA`           | Optional native CA certificate path; otherwise system trust                                                               |

The gateway shares one native `WatchEvents(all)` subscription across browsers. Its replay ring is bounded to 2,048 events and 4 MiB; each browser has a 256 KiB write budget. Slow consumers are disconnected without pausing native delivery. Reconnects preserve the native sequence cursor and require snapshots after gaps or faults. `ATX_WEB_MAX_STREAMS` sets the browser connection cap (default 512; range 1..4096).

`ATX_WEB_RATE_LIMIT` sets the per-IP request budget per minute (default 240; range 1..1000000). Increase it deliberately for shared NAT or an HTTPS reverse proxy. Forwarded client addresses are never trusted: `trustProxy` stays false, so reverse-proxy traffic shares the proxy's rate bucket. UI event refreshes are coalesced at one second and terminal result documents are cached only for the selected job. Direct native streaming clients retain the server's independently bounded subscription limit.

Web and server tokens are separate. Browser credentials remain in memory and are never stored in local storage or SSE query strings. Expose non-loopback HTTP through an HTTPS reverse proxy. The gateway rejects cross-origin browser mutations, sets CSP and no-store headers, bounds API requests and SSE clients, forwards cancellation, uses 15-second unary deadlines, and stops active channels during shutdown. SSE reconnects with its last sequence and refreshes durable snapshots after replay gaps. Job wire statuses are lowercase; future scheduled jobs remain `queued` with `scheduled_at_ms` until the native scheduler starts them.

NAV imports refer to existing CSV artifacts inside the native server's allowed roots. The browser does not upload or overwrite artifacts. The request editor supports the backend's audited alpha DSL through `strategy_dsl`, including `rank(delta(close,5))`; the native engine parses, compiles and evaluates it.

The saved-blend native replay mode requires both combined and role artifact paths and their SHA-256 hashes. It uses TRAIN observations with the library's declared cost scenarios and initial NAV. Provenance retains the artifact and recipe pins; the UI reports research-unverified observations and does not claim capacity qualification.

## Research pipeline

**Observed TRAIN data** selects an operator-registered dataset and pins its manifest SHA-256 in the draft. The editable DSL is validated by the native compiler using **Validate expression** or **Ctrl+Enter**. The dockable **Operators** panel lists the actual supported expressions and examples. Validation reports syntax, fields and causal lookback; a successful check does not certify investment performance. Runs use the configured execution delay and costs on actual observations. Historical vintage, historical common-stock membership, capacity and borrow qualification remain explicitly unverified.

**Alpha library** saves the current recipe or selected run recipe with a name, tags and hypothesis. Every edit creates an immutable revision; head updates and archive changes use exact revision strings and preserve conflicting edits. **Load recipe** explicitly replaces the editable draft. **Run revision** submits the alpha ID and exact revision separately, so the native service resolves the frozen recipe and retains the lineage on the job. Uncommitted library forms must be saved or discarded before saving their workspace.

**Comparison** aligns two to twelve successful jobs by exact daily-return periods, then recomputes metrics and correlations on that intersection. Its curves are rebased for comparison, not combined into an executable portfolio. Mixed synthetic and observed evidence requires explicit opt-in; excluded periods, gaps and unavailable statistics remain visible.

**Experiments** submits one to thirty-two simulations atomically. Add a frozen copy of the current recipe, expression variants using the current dataset/cost assumptions, or an exact saved alpha revision. Give the cohort a name and run immediately or choose a future schedule. History shows native member counts and progress; **Inspect** loads a member's actual results, and **Cancel experiment** cancels outstanding members without rewriting completed ones. The unsent composer is part of a named workspace; admitted cohorts and member jobs are durable native records.

**Recurring workflows**, central in the Operations template, schedules a frozen recipe or exact saved alpha revision at a fixed UTC interval from one minute to thirty days, with a finite budget of up to 1,000 admitted runs. Dataset pins and evaluation dates stay frozen; this is not an exchange calendar or rolling-data scheduler. Missed slots are coalesced and executions never overlap. History shows exact counts, slot lineage, permission/source pauses and dispatch errors. **Pause** prevents new admissions while leaving an active job running; **Cancel active workflow run** cancels that job separately. **Resume** retains the budget and uses the exact lifecycle revision. Completed workflows cannot resume. Changing configuration requires **Copy workflow configuration** and creating a new record. Researchers can create and control workflows; viewers can inspect their durable runs. Unsent composers are saved in named workspaces without admitting a schedule.

**Portfolio construction** edits two to twelve embedded observed-data expressions with exact UTF-8 SHA-256 hashes and signed manual weights. **Validate and pin components** checks each expression through the native compiler and preserves edits made while it is working. Copying a saved expression freezes its exact text; it does not assert a native alpha reference. Shared dataset/date/cost/delay settings remain in **Draft configuration**. Native execution standardizes and combines signals, then solves constrained delayed targets with identity geometry; it neither averages NAV curves nor claims an estimated covariance risk model. Target gross, name and turnover limits use pretrade NAV, while the allocation evidence separately reports achieved posttrade weights, costs and strict solver residuals. Infeasible or unconverged solves fail without relaxing limits. The native aggregate compute budget may require fewer names, shorter windows or larger cadence.

## Database viewer

**Database viewer** is a regular docking panel, initially tabbed alongside **Draft request** and available from **Windows** for saved layouts. Select a configured source, schema and table to load a bounded preview. The table list supports filtering; preview pages support previous/next navigation. Preview order is not guaranteed: use `SELECT ... ORDER BY ...` when row order matters.

The **Database** toolbar button opens the panel directly. Bookmark `/?panel=database` to open it on arrival while retaining the saved docking layout. Database tables render visible rows with a small scroll buffer, preserving sticky column headers and horizontal scrolling for wide results.

The query editor supports **Ctrl+Enter** and **Run SELECT**. Requests are read-only and respect the provider's reported limits, bounded to 500 rows, an offset of 1,000,000, and 64 KiB of UTF-8 SQL. Results identify their source/table or query, show column types, retain exact database text for large integers and decimals, distinguish SQL NULL from the literal text `NULL`, and display truncation and provider warnings. Editing or switching the request clears stale results; cancellation stops the pending browser request and propagates to the native call.

Sources, metadata, SQL policy and database access belong to the native provider. The gateway uses the provider-neutral gRPC contract through `/api/data/sources`, `/api/data/catalog`, `/api/data/preview` and `/api/data/query`; it imports no database driver. Browsers select curated source IDs and cannot change configured source paths or connection credentials. Read-only SQL may reference files inside operator-approved roots; the native provider validates access. Busy/unavailable providers, execution deadlines and capacity limits show safe actionable errors.

## Team identity and reviews

An operator-configured native team uses `ATX_WEB_TEAM_AUTH=1` on the gateway. Enter your individual credential through **Access**; the gateway forwards that credential to native calls and does not substitute its internal service credential. The current native actor and role appear in the title bar. This release has one explicitly shared local project, not private project isolation. Standalone native sessions identify the local operator as admin.

Roles are cumulative: viewers browse, researchers submit research and edit shared records, reviewers also approve or reject evidence, and admins retain all capabilities. Native authorization remains authoritative. Browser credentials stay in memory and never enter workspace documents, alpha recipes, audit records or query strings. The dockable **Team / audit** panel shows configured members and credential expiry, then pages through durable native audit records by actor and entity.

**Research reviews** freeze an exact alpha revision and one to twelve linked successful runs. The evidence JSON remains inspectable. A team approval or rejection requires a reviewer distinct from the requester and all recorded authors of that frozen recipe; standalone sessions explicitly allow self acknowledgement. Approval requires the alpha revision to remain the current research head. The requester or an admin can withdraw a submitted or approved review. Decisions require a rationale and exact compare-and-swap revision; conflicts retain the rationale while reloading the latest record. Approval records an acknowledgement, not certification of data history, capacity or future returns.

## Validation

`npm test` checks auth, request translation, origin rejection, pagination, error mapping, malformed native documents and actual HTTP SSE replay/cancellation. `npm run build` runs strict TypeScript checking and the production build. `npm run test:e2e` validates real browser docking, edge splits, persistence/reset, compact layout and request editing against the served production assets. The browser tests default to the installed Windows Chrome; set `ATX_CHROME_PATH` for another local Chromium executable.

For full native lifecycle validation, start `atx-server` and enable `ATX_E2E_LIVE=1`, `ATX_E2E_DATA_LIVE=1`, `ATX_E2E_WORKSPACES_LIVE=1`, `ATX_E2E_PIPELINE_LIVE=1`, `ATX_E2E_EXPERIMENTS_LIVE=1`, `ATX_E2E_GOVERNANCE_LIVE=1`, `ATX_E2E_PORTFOLIO_LIVE=1` and `ATX_E2E_WORKFLOWS_LIVE=1`, then run `npm run test:e2e`. Use a disposable database: gates create durable test jobs, experiments, reviews and workflows. The database gate requires a configured `atx-db` source. TRAIN and portfolio gates require the registered `atx-equity-panel` dataset. The workflow gate verifies finite completion, durable reload, frozen alpha revisions and pause/resume. Team qualification additionally uses `ATX_E2E_TEAM_LIVE=1`, `ATX_E2E_TEAM_BASE_URL` and disposable researcher/reviewer/viewer credentials in `ATX_E2E_TEAM_RESEARCHER`, `ATX_E2E_TEAM_REVIEWER` and `ATX_E2E_TEAM_VIEWER`. To test an already running gateway instead of the isolated port-3001 test server, set `ATX_E2E_BASE_URL`. Screenshots are saved under `artifacts/`.
