## Units, types, clocks and population

Each batch gets a new UUID attempt and a start receipt written before calculation. Native calculation writes isolated `events`, `sic`, `history`, `catalog` parts and its own receipt. Admission requires an exact native schema, nonnull typed source keys, unique keys, actual source CIK/accession population, valid available/filing clocks, event/catalog population agreement, and full native replay equality of all four Parquets and counters. Timing fields are excluded from semantic receipt equality. No `_batch_done` or existence-only skip is consulted. Interrupted unsealed attempts are retained and recomputed into a new attempt; an admitted unit is immutable and rechecked rather than overwritten.

Event/catalog/SIC keys are `(cik, accession)`; history keys retain native `(cik,item,period_end,fiscal_period,accession)` including genuinely nullable fiscal_period. History warmup before the event emission floor is preserved. Exact schemas and replay prevent changing the availability clock, inventing a zero, changing currency, inserting a source-unsupported CIK/accession, shrinking missingness, or editing a value while preserving a valid footer. Final outputs merge explicit admitted file lists; cross-batch duplicate keys and exact native final schemas are checked, then final Parquets are independently compared to the admitted-unit merge including 8-K ASOF nonreliance clocks and native classifications.

## R19 bounded extraction validation and external admission

`validate-extract --bindings <absolute-source-binding.json> --batch <0..84> --receipt <absolute-new-receipt.json>` completes exactly one ZIP extraction replay. It checks the full 85 ZIP batch/member and 256-file name inventory, hashes the actual archive, plan, selected payload/statistics/native receipt and actual code/frozen contract before work, and rechecks them afterward. Only the selected batch's source files are read and hashed; other batches are required by inventory but remain unvalidated. Both Parquets must have exact native schemas and identical typed multisets, including multiplicities, and all native member/error populations and counters must match. Original source CIKs are derived from ZIP members, never selected from the candidate receipt. No one-batch command admits the whole source.

A successful command returns its receipt path and physical SHA256/bytes. The receipt is a deterministic full validation record containing the separate source identity, all 85 planned member lists, selected source pins, relevant code/contract pins and complete validation populations/counters. It excludes the source binding's own digest and the external admission digest, avoiding a circular binding. Before replay a unique `attempts/<uuid>/start.json` records the source/binding pins. Failed or interrupted attempts retain forensic starts/partials and cannot be reused. Fully flushed receipt bytes are published by an atomic exclusive hard-link; an existing receipt is never replaced. The root controller must independently admit successful guarded executions. Receipts alone, source receipt claims, marker files and receipt existence grant no reuse.

The controller's external admission JSON must have exactly `{"version":"fund-extract-validation-v1","receipts":{"0":{"path":"<absolute receipt>","identity":{"sha256":"<reviewed hash>","bytes":123}}, ...,"84":...}}`. Every original batch is mandatory; paths must be absolute, unambiguous and distinct. JSON duplicate keys are rejected. The external admission file must be outside mutable extraction, preparation and release candidate directories. Callers supply both `--extract-admission <absolute-controller-file>` and `--expected-admission-sha256 <independently-pinned-physical-file-hash>`. The file's own asserted digest or inventory is never sufficient. Changing this file requires new caller admission; unchanged hashes inside a rewritten file cannot retain the old expected identity.

`freeze(..., extract_admission=path, expected_admission_sha256=hash)`, `build` and `validate_generation` may replace extraction replay only with this explicit caller authority. They still rehash actual source/code/product bytes and compare complete receipt semantics against current identities. All 85 receipt pins are verified again after consumption. The source binding remains independent; the frozen snapshot separately retains the external path, actual identity and complete admitted inventory. Continuation cannot remove/change that frozen admission or select another file. A candidate snapshot's embedded admission does not authorize cached public validation: callers must again supply the external expected path/hash. Omitting them performs full extraction replay. `--force-full-replay` explicitly ignores the reuse optimization while preserving/rechecking the admitted identities. Rollback/recovery retain their default full replay.
