# Fundamental signal research in the Tier-1 measurement

Run `scripts/measure_tier1_readiness.py` with `--include-fundamental-signals` to add `fundamental_signal_research` to the existing read-only JSON and Markdown artifacts. The default is `{"status":"not_requested"}`. The report-wide `certification` remains `unmeasured`.

The optional section inventories FQ1 build manifests and FQ2 evaluation manifests separately. An absent table or required column appears as a separate schema gap. If FQ1 schema is missing, the latest FQ2 run remains visible while linkage and summaries are unmeasured. Run inventories contain at most 1,000 rows each and carry a `truncated` flag. Each manifest is selected from complete runs observed on or before the report date, ordered by `run_at` and then `run_id`. The selected FQ1 manifest displays its build snapshot and requested start/end dates. Its grouped coverage describes only that run's stored decision sessions. It never reads score values, input rows, or proofs.

The latest complete FQ2 manifest is linked to a complete FQ1 manifest whose build snapshot is on or before both the evaluation and report dates. Frozen FQ2 summaries appear only when its recorded `build_sha256` equals the linked build's recorded `panel_sha256`. A mismatch leaves the latest evaluation visible as a diagnostic but suppresses candidate rows; an older evaluation is not substituted. Summary `recorded_research_candidate` is a stored research flag. Blocker count is read from manifests; blocker text and arbitrary manifest JSON are not transferred. Unknown status and identifier text is reduced to fixed safe labels.

The section does not run the FQ1 panel validator, recompute a digest, reread FQ2 labels, or infer significance, alpha, production eligibility, or Tier-1 parity. Recorded hash equality and completion are observations only. The measurement retains the script's single read-only snapshot, bounded result handling, memory/spill controls, and exclusive output filenames.
