# Bounded equity panel: first training block — 2026-09-19

Implement a separate, small baseline panel path rather than optimize the existing sixteen-field assembler in place. The first implementation evaluation window is explicitly **[2013-04-04, 2014-01-01)** with **256 preceding source observations**, top 1,000 by causal 21-observation raw-dollar ADV, ADV ≥ $20m, raw close > $5, and a **3,000,000,000-byte process working-memory target**. April 4 remains provisional until accepted-input dates confirm readiness. These are declared research settings, not liquidity or investment certification. This review read code and existing audits only; it did not scan the ZIP or inspect sealed-period returns.

The existing `build-equity/audits/tbltickerhistory-input-profile.json` date-count metadata shows **253**, not 256, observations before the initially assumed 2013-04-01; that April 1 evaluation would have 192 source dates. The first source date with 256 preceding observations is **2013-04-04**. The explicit first-block revision was made before any strategy metrics; the overall training partition remains unchanged. Recheck accepted dates and reject if April 4 cannot provide all 256 observations, never silently move it or underfill warmup. Four context dates have positive-ID collisions, so the original source also needs the established quarantine-all-duplicates preparation policy. These findings used stored date/count metadata, not a new archive read or strategy returns.

## Smallest explicit API

New engine files: `include/atx/engine/data/bounded_equity_panel.hpp`, `src/data/bounded_equity_panel.cpp`; no edits to generic `Panel`, APNL or the old history builder are required for phase one.

```cpp
struct DailyEquitySource { std::string path; i64 session_key; u64 size_bytes; };
struct BoundedEquityConfig {
  alpha::TimeWindow evaluation; // half-open, UTC-ns session labels
  usize warmup_observations{256}, adv_observations{21}, top_n{1000};
  f64 min_adv_usd{20e6}, min_raw_price_exclusive{5};
  u64 max_working_bytes{3'000'000'000};
};
// Plan owns metadata, canonical axes, compact indices and sparse per-date eligibility.
Result<BoundedEquityPlan> plan_bounded_equity_panel(
    span<const DailyEquitySource> sources, const BoundedEquityConfig&);
// Source bytes must match the plan's bound snapshots; no selection is recomputed differently.
Result<BoundedEquityPanel> materialize_bounded_equity_panel(const BoundedEquityPlan&);
```

`BoundedEquityPanel` owns `Panel panel`, `session_keys`, canonical positive-i64 `instrument_ids`, `original_instrument_indices`, selected `source_segment_paths`, `evaluation_begin`/`evaluation_end` row offsets, and deterministic counts/estimates. Plan stores only selected daily source descriptors, first-seen source ID dictionary, per-date compact eligibility lists, quality exceptions, and checked allocation bounds; it never owns a full raw grid. Hashing and publication remain in `atx-impl`, which binds each selected source before planning and verifies those exact bytes afterward. If plan/materialize reopen a source, check that source hash at each pass boundary, not only a final directory listing.

New impl helper files: `src/bounded_equity_panel_stage.hpp/.cpp` for daily-source selection, quality policy and identity recipe; `src/equity_baseline_views.hpp/.cpp` for explicit feature/evaluation views and signal masking. `stage_panel.cpp` only dispatches the new profile. Proposed config additions (not available today): `--panel-profile equity-baseline-v1`, `--evaluation-start`, `--evaluation-end`, `--warmup-observations`, `--max-panel-working-bytes`. Require explicit evaluation bounds; reject conflicting legacy `--start/--end`, augmentation, sector/market-cap screens and incremental mode for this profile. Root owns config/CMake changes when implementation is authorized.

## Source selection and two data passes

1. **Select metadata before mapping.** First support only this native loader's `YYYY-MM-DD.seg` daily partition format, with exactly one timestamp per file matching the filename. Resolve names using the existing strict date parser, select evaluation dates from 2013-04-04 through 2013-12-31, and the latest 256 distinct earlier dates; refuse insufficient warmup instead of inventing it or shifting the requested period. File names are candidates, not trusted dates: attach each selected file and validate its actual axis before using any cells. Reject multi-date/misnamed files explicitly rather than fall back to mapping the whole directory. A generic row-index manifest can be a later extension if an actual input requires it.

2. **Bound the source set.** Canonicalize selected paths inside the requested directory; accept only regular native segments, reject aliases/duplicate dates. Resolve required segment fields once per file: raw `close`, `volume`, `cumReturnFactor`; additionally inspect original OHLC and source return fields when the selected-window quality gate requires them. Check every source ID as canonical positive i64, duplicate IDs/present cells and source timestamps before screening, including names that will be discarded. Source hash/provenance binds complete files, not just the retained fields. The engine return paths must match the selected manifest exactly.

3. **Pass one: causal eligibility, no dense prices.** Walk selected dates ascending and source columns in stored order. Maintain a 21-value ring and last global-date index per source ID. A missing/padding date or invalid raw price/volume breaks the full window; a later observation cannot close a historical gap. Compute dollar volume from unadjusted price times reported volume; zero volume is valid, and a zero ADV cannot pass the $20m floor. Reject overflow, nonfinite values and positive-product underflow explicitly. Sum the 21 values oldest-to-newest for deterministic parity with current `build_universe`, rather than a history-dependent running-sum update.

4. **Selection timing is explicit.** At decision date `d`, ADV uses `[d-20,d]`, including that close/volume. This matches the existing universe convention; replay delay one remains a hypothetical next-observation execution convention, not historical availability evidence. The report's trade/ADV statistic independently uses 21 observations strictly before the execution observation. Mask all warmup rows ineligible. For each evaluation date, screen present, numerically valid marks, raw price and ADV; sort by descending ADV, then original source ID index for ties, matching current universe order. Save at most top-N IDs for that date. No ranking by future ADV or end-of-window membership.

5. **Freeze the compact axis.** Original index means first-seen source-column order while scanning only the selected context in actual date order, with deterministic path tie-breaks; it is local ancestry, not a global security number. Keep the union of IDs eligible on any evaluation date, retaining original order. Warmup eligibility does not select extra names; their observations may still be needed for IDs selected later. For future stateful blocks, add every carried ID and preserve its mark history regardless of eligibility; phase one starts flat and explicitly rejects nonempty carried state until continuation is implemented. A union can affect storage shape, never earlier cross-sectional membership or weights.

6. **Preflight before pass two.** Count `D`, source IDs `U`, retained IDs `K`, eligible pairs `E`, source-file sizes and metadata bytes. Use checked integer products/additions before vector allocation; reject empty selection, negative/nonfinite thresholds or unrepresentable dimensions. Resolve the memory estimate below, including the immutable plan. A failed budget emits the plan/quality report and no panel success manifest.

7. **Pass two: fill four columns only.** Allocate `4 * D * K` doubles once plus one `D*K` byte decision mask. For each selected date, reopen/verify just its segment, look up retained IDs, and fill canonical columns `close`, `raw_close`, `volume`, `observed`. `close=raw_close*cumReturnFactor` with checked finite positive product; raw price and raw volume are untouched. `observed` is exactly 0 or 1 and records accepted numerical price/volume presence, not asset-type eligibility, original publication or economic certification. Absent/invalid marks remain NaN/observed=0; never forward-fill a held price. Decision mask comes from the frozen pass-one lists and must imply observed=1. Close each reader before opening the next; do not retain per-file field spans past the mapping owner.

## Four fields require an explicit consumer adapter

Keep the normal `Panel` universe as **decision eligibility**; do not globally reinterpret it. Persist `observed` because a future eligible entrant needs valid warmup prices even when historically outside top-N. Build a temporary borrowed feature panel over the same numeric columns, with `observed` converted to a byte mask. Run only the two frozen time-series/arithmetic DSL programs on that view. Phase one rejects cross-sectional/group/stateful operators in this profile; evaluating them across the storage union could introduce future selection dependence.

After VM evaluation, explicitly replace each constituent signal cell with NaN unless it is in the evaluation window, decision eligible, and **both signals are finite**. This common readiness gate prevents the 126 variant from trading alone before the 252 variant is ready. Existing [`extract_streams`](../include/atx/engine/alpha/streams.hpp) builds a static full-size `Universe` and relies on masked signals; passing a differently masked `Panel` alone does not enforce eligibility. Its public `SignalSet::Alpha::values` allows this local in-place gate before any rank/winsorization. Reuse `WeightPolicy` on the resulting eligible cross-section, not on every observed or retained ID.

The longest frozen expression first has a full value at local index 256: `delay(close,252)` followed by a five-observation mean. Require 256 preceding **source observations**, not 256 calendar days; no exact exchange-calendar coverage is inferred. A legitimate numerical gap may keep an individual name unready longer; report that count without backfilling. Changes to later data may change compact storage but must leave earlier surviving IDs' signals, eligibility and weights identical.

A feature-context panel is **not yet a scored research panel**. The baseline driver must crop borrowed columns/signals to the evaluation rows, rebase decision indices, publish a derived evaluation identity with the full context/selection/DSL parents, and anchor initial NAV at its first row. Generic `run_optimize` schedules from row zero; `fit-begin` does not block warmup orders. The new profile reader must require this adapter and reject generic combine/optimize consumption until it is integrated, instead of letting callers silently receive the old mask semantics. No book/report during the initial builder-only acceptance step.

The equal blend can be applied without an estimated covariance fit. A later shrinkage comparison needs a distinct fit-once/apply-frozen combiner artifact across blocks; current `.weights.txt` is output-only. That interface is not a reason to expand this builder's first slice.

## Memory estimate and explicit stopping point

Let `C=D*K`, `A=2` signals, `S=Program::num_slots`, and `M=max selected segment bytes`. A final four-field numeric panel plus mask is `33*C` bytes. Budget at least another `33*C` during APNL write or verified read (both currently materialize a payload buffer), the plan/ID dictionaries and eligibility lists (`O(U*21 + E + D + K)`), one source mapping `M`, and conservative allocator/runtime overhead. Hashing can stream fixed buffers; no second complete archive or segment-set copy is needed.

Before evaluation, separately budget the owning panel, `C` bytes feature mask, `8*S*C` VM slots, `8*A*C` SignalSet, and the constituent position/store buffers currently copied by combine (at least another `16*A*C`), plus output and model workspaces. Compile the two programs first to obtain the exact `S`; no default-worker multiplication. Release stage-scoped arrays between build, serialization and evaluation. Solving a risk book is a separate budget with active plus carried dimensions and factor/solver scratch explicitly included.

For illustration only, `D=600,K=5,000` gives `C=3m`: final payload about 99 MB including mask, writer overlap about 198 MB, and a six-slot/two-signal evaluation lower estimate about 294 MB before at least 96 MB of combine copies and other workspaces. With `U≈25,000`, a 21-double ring is about 4.2 MB plus state/maps. These arithmetic estimates are not RSS measurements or proof that source selection yields 5,000 IDs.

Stage preflight must leave reserve for native runtime and the largest mapping, then measure peak private bytes/working set in the actual Windows run. If estimate or measured bound is exceeded, fail this declared block. A coordinator may propose a smaller block with the same universe policy, but the complete warmup plus one evaluation row and all required names is a non-shrinkable floor. If that floor exceeds 3 GB, return a bounded-memory error and redesign storage/solve execution; never loop halving forever, truncate warmup, or drop held names.

## Economic status and provenance gates

This builder verifies source bindings, numeric quality and a deterministic transformation; it cannot authenticate total returns. The [KLAC audit](2026-09-19-klac-source-adjustment-audit.md) proves that a positive source cumulative factor can still omit a real split. [`TickerHistory3`](https://docs.spiderrockconnect.com/docs/next/HistoricalData/Data%20Dictionaries/TickerHistory3/) describes daily and cumulative factors but does not make this downloaded snapshot revision-aware. Do not infer new corrections from jump sizes or vendor-field agreement alone.

For the 2013 phase, inspect/reconcile only the selected warmup and evaluation input, using a versioned bound quality report. Missing economic attestation is `unverified`, not `passed`; known unresolved contradictions are `failed`. Always allow a metadata/memory plan. Qualified-book materialization/admission must explicitly reject unverified/failed economic status. A separately declared **archive diagnostic** may publish an unverified numerical context with that status in its recipe, but cannot be promoted or labeled a verified return dataset. This distinction must be part of the invocation/manifest, not an inferred exception after attractive results.

Publish a required profile recipe containing evaluation/context bounds, actual warmup count, four-field order, both mask meanings, inclusive ADV window, tie rule, original-index scope, thresholds, common-readiness rule, memory estimate/limit, quality-report SHA/status, source calendar status, unknown instrument type/availability, and producer executable hash. Bind every selected warmup/evaluation segment SHA and the verified ingestion/preparation chain. Bind the selection-plan digest as another parent; make source changes between passes fatal. Exact axes remain decimal strings under existing `PanelIdentity`; no hash claims historical publication or shares correctness.

Reuse fresh `.stage-lock` reservation, validated source snapshots and `write_panel_artifact` manifest-last publication. Quality/planning reports may survive a failed run, but there must be no complete panel manifest claiming success. Do not include wall-clock duration/RSS in deterministic identity; retain those measurements in a linked receipt.

## Focused acceptance, then the first real build

- Tiny native daily segments: late entrant has 256 usable observations while previously ineligible; feature momentum is correct, rank/weights consider only current eligible ready names, and zero warmup trades/scored returns result. Test both the static-Universe trap in `extract_streams` and forbidden cross-sectional feature operators.
- ADV oracle: inclusive 21-observation oldest-to-newest sum; raw rather than adjusted prices; zero volumes; one missing global-date cell; exact ties; padding cannot erase observations; future new IDs/changed future values cannot change earlier eligible results.
- Source and identity: misnamed/multi-date/reversed files, duplicate/noncanonical IDs, duplicate present cells even when discarded, source changed between passes, absent required field, and exact retained original mapping. ID >2^53 remains an exact string. A sealed-period file outside the explicit source selection is never attached.
- Budget/quality: checked size overflow before allocation, one giant daily file, plan over budget, non-shrinkable floor, insufficient warmup, factor/product overflow or zero, unresolved economic report and a held gap. No invented price, silent selection reduction, or completed output on rejection.
- Parity/evidence: on a small valid fixture with observation=eligibility compare selected axes, inclusive ADV/mask and direct source prices to the old path; independently verify all four fields on retained native rows. Compare full versus blocked feature/evaluation results with explicit state assumptions, not merely aggregate digest.
