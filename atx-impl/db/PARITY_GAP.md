**Known standing quality failure — calculation-linkbase (characterized, S34 triage):** the `failed_xbrl_calculation_linkbase_checks` check reports **1,364** failed rows over only **5 securities / 11 filings**. These are **structural dimensional-context mismatches, not a tolerance bug**: the SQL validator sums a parent calculation total (`parent_value`) against a `child_weighted_sum` computed from an incomplete/mismatched child set — e.g. `AssetsFairValueDisclosure` parent `$1.33T` vs child sum `$8.93B` with `child_count=2`, where the parent is a dimensional roll-up and only the undimensioned children were summed (or vice versa). 1,362 of 1,364 have `absolute_difference >= $1M`; only 2 are near the flat `$1` tolerance. A correct fix requires **dimension-aware calculation validation** (matching parent and children within the same `context_ref` / dimensional member set, per role_uri), which is a substantial XBRL-engine change with high blast radius on the fundamentals validation path — deferred, not suppressed. Do **not** "fix" this by loosening the tolerance; that would hide real structural errors.
