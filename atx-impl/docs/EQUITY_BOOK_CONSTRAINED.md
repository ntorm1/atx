# Constrained equity book - engineering profile, 2026-09-20

`equity-book` applies the engine's constrained allocator to the fixed baseline preferences using actual marked holdings at each delayed execution. It adds decision-time diagonal risk, dollar neutrality, exposure limits and a hard trade budget to the existing daily cash/holdings replay. The current engineering profile is `constrained-preference-weekly-observed-close-v3`: an unheld name without a valid current execution close receives a zero-weight equality before optimization, then allocation becomes explicit weight, hold or close instructions. Its latest native attempt has four independently verified proposals and 18 complete intervals, but fails on a later missing held mark. There is no completed performance result.

Development and builds now run from **`C:/atx/.worktrees/equity-platform`**. The isolated worktree preserves the recovered equity changes after an external stash/restoration changed the original checkout. Research inputs and new attempt outputs remain under `C:/atx/data`.

```powershell
Set-Location C:/atx/.worktrees/equity-platform
build-equity/bin/atx-impl.exe equity-book `
  --panel C:/atx/data/tickerhistory_training_native_20260919/context.bin `

  --out C:/atx/data/equity_book_training_2013_observed_close_new_attempt `
  --max-working-bytes 3000000000 --report-aum 100000000 `
  --replay-execution-delay 1 --replay-trade-bps 5 `
  --replay-annual-borrow-bps 365 --replay-day-basis 365
```

The output directory must be absent. Use another new path for a repeat attempt; existing outputs are never overwritten. This command retains the baseline's complete evaluation window, 2013-04-04 through 2013-12-31 for the named inputs. Evaluation-date overrides are rejected. The command accepts only training artifacts before 2020 and verifies the actual every-five-observation schedule, instrument axes, source ancestry and exact evaluation slice.

The source context supplies the warmup history. The baseline directory supplies identified `evaluation.bin`, `combo.bin` and `books.bin`, their manifests, the book schedule and the combination fit metadata. A baseline that failed its fixed-target replay may still supply these completed intermediate artifacts; a completed outer baseline manifest is not required. This preserves a failed trial while testing a different allocator against the same full data window. Missing held marks still reject the entire new replay. The [source audit](../../atx-engine/reviews/2026-09-20-equity-required-marks-audit.md) documents unresolved observations and representative terminal corporate events; this command does not repair them.

The signal family and equal combiner remain those of [the baseline](EQUITY_BOOK_BASELINE.md): skipped-month 126- and 252-observation momentum, each smoothed over five observations, with common readiness and the existing rank/winsorization position transform. Scheduled baseline book weights become preferences for the constrained solve. They are not calibrated expected returns. There is no additional alpha search or combiner fit in this command.

| Control | Frozen value and interpretation |
| --- | --- |
| Objective | Minimize `0.5 * sum((w - preference)^2) + sum(variance * w^2)`; risk penalty 1. |
| Risk history | Population variance of 63 adjacent total-return-price returns from 64 context observations ending at the original decision; floor `1e-6`. No execution-date or future return is used. |
| Schedule | Original evaluation rows `0, 5, 10, ...`; default execution delay one observation. This is observation-based, not calendar-week scheduling. |
| Immediate post-fee exposures | Net zero, risky gross at most 1, absolute name weight at most 0.01, checked within `1e-8`. Gross is an upper bound, allowing a gradual startup from cash. |
| Trade budget | Full L1 actual traded dollars divided by pretrade NAV, at most 0.20 per rebalance, including entry and mandatory exits. No annual turnover cap is implemented. |
| Execution-price availability | `ObservedCloseEntryConstraintV1`: exact-unheld names with absent/nonfinite/nonpositive current closes receive a pre-solve zero-weight equality. Keep the original solve union; all held marks remain required. |
| Numerical solve | Fixed 1,200 ADMM iterations, rho 1, sigma `1e-6`, configured row tolerance `1e-8` tightened for aggregate error and fee amplification, ten Ruiz passes, polish enabled with three refinement passes; primal/dual residual gate `1e-6`. |
| Default charges | Five bps per absolute dollar traded; annual simple short financing 365 bps using actual calendar time/365. The baseline's resolved charges, delay and AUM are inherited when no override is supplied. |
| Factor payload | Each ADMM/polish factor has a 256 MiB limit on `Lp/Li/Lx/D/Dinv` requested storage, checked against actual symbolic fill. Other arrays have a separate conservative admission bound. |

The turnover reference is the execution-time marked portfolio, including holdings that have left decision eligibility. The solve includes every eligible risk-ready name and every held name. Ineligible positions are fixed to zero. A new name without all 63 valid adjacent risk returns cannot enter; an eligible held name lacking that history rejects allocation. An ineligible held name can exit without an estimated variance, provided its execution mark exists. Mandatory exits that cannot fit the hard trade budget cause failure; the command does not relax constraints or delete holdings to pass.

The stage explicitly selects `ObservedCloseEntryConstraintV1`; the public helper defaults to `RequireRequestedMark`, preserving its previous strict behavior for requested entries. The opt-in rule is `held_TRI_units == 0 && !finite_positive(current_execution_close)`. It adds an identity-box equality before the solve, keeps the name in the eligible/risk-ready union, and leaves frozen preferences, decision eligibility, risk estimates and solver controls unchanged. Other positions are reoptimized under the original constraints; an unpriced entry is not clipped from a solved book afterward. The same required-zero reasons govern exact lifting, intent selection and final economic certification. An unavailable unheld name creates no trade or fee, while changed trades in other names still incur actual fees and turnover. A later valid current observation can permit entry under the applicable frozen decision and risk rules.

This is an execution-price availability convention within the existing simultaneous hypothetical-close model. An absent vendor close does not establish an exchange halt, zero real market volume or a rejected order. There is no execution-day volume filter, future-coverage requirement, permanent exclusion, fallback solve or window shortening. Held mark validation occurs before the callback, including before any mandatory Close. Seeing a final closing price or its absence and then filling at that same price is not a validated close-auction strategy: the source lacks publication/receipt times, and `available_by_order_submission` remains `unverified`. Current [NYSE auction timelines](https://www.nyse.com/trade/auctions) illustrate the order-cutoff issue; they are not asserted as historical rules for the full sample. The [iteration 11 design](../../atx-engine/reviews/2026-09-20-iteration11-execution-availability-design.md) compares conditional optimization with rejected-order alternatives and explains potential selection bias from historical missingness.

Our 0.20 trade budget counts both purchases and sales in full. Cvxportfolio defines its turnover constraint as half the noncash trade-weight L1 norm, so the corresponding numerical limit under that convention is 0.10. This conversion is a convention comparison, not solver equivalence. [Cvxportfolio `TurnoverLimit`](https://www.cvxportfolio.com/en/stable/constraints.html#cvxportfolio.constraints.TurnoverLimit).

Before solving, the allocator reserves for the maximum permitted fee: gross/name bounds in pretrade-NAV units are multiplied by `1 - (trade_bps * 1e-4) * turnover_limit`. At the command's base rates this factor is 0.9999. The independent allocation certificate then reproduces representable TRI-unit sizing, dollar trades, cash debits and post-fee NAV, and checks actual turnover and final net/gross/name exposures. Solver success alone does not authorize a candidate. The internal row tolerance is at most economic_tolerance * fee_reserve / [8 * (2M + 1) * (1 + fee_rate * (1 + gross_limit + name_limit))], where M is the active-plus-held count. This prevents individually small auxiliary-row errors from accumulating beyond the full-L1 economic budget; a rejected polish retains the original solver candidate, subject to the same independent checks. The continuous solver evidence is preserved; the separately declared representation rule below is followed by full economic checks. Risk/exposure limits apply immediately after allocation; subsequent price drift between rebalances is recorded but not continuously constrained.

The continuous solver output remains unchanged in the evidence. The explicit representation layer applies a separate, declared rule. With `c` the fee rate, `r = 1 - c * turnover_limit`, canonical instrument count `N`, gross limit `G`, name limit `B` and economic tolerance `tol`, its ordinary correction budget is `tol * r / (128 * (1 + c * (1 + G + B)))`. Per-name `eta` is the smaller of that budget divided by `N` and `64 * binary64_epsilon * max(1, abs(raw_weight), abs(previous_marked_weight))`. Mandatory closes take priority; otherwise `abs(raw_weight) <= eta` selects Close, then `abs(raw_weight - previous_marked_weight) <= eta` selects HoldCurrent, and all remaining names select TargetWeight. Selection uses the causal allocation and current validated holdings, without future missingness or threshold retries. Existing helper callers retain the exact-weight default.

HoldCurrent preserves held TRI units and marked dollars bit-for-bit with zero trade delta. Close sets exact zero units and charges the real closing trade. Current held marks remain mandatory for either action; flat Close does not require an unused entry mark. After representation the full book is recertified against the unchanged cash, NAV, net, gross, name and actual-turnover limits. Required-zero lifting is recorded separately from the ordinary correction budget, with separate decision/risk and execution-price components; total raw-to-actual exposure change also includes sizing roundoff. Raw solver residuals describe the continuous solution to the QP including its required-zero equalities; represented objective and stable objective change are separate fields. They do not certify optimality after representation. This is a numerical representation convention, not a cash minimum, physical share rounding or an economically optimal no-trade region. See the [design](../../atx-engine/reviews/2026-09-20-equity-execution-representation-design.md) and [independent review](../../atx-engine/reviews/2026-09-20-allocation-representation-review.md).

The engine uses a deterministic direct KKT factorization with a separate active-set polish. Checkpoint 9 corrected refinement to target the unregularized KKT system through the existing regularized factor, retaining four fixed correction solves. It now checks a coherent primal/dual candidate, including normal-cone and feasibility conditions; an infeasible incumbent's lower objective cannot veto a feasible repair. Ordinary unsuccessful numerical polish retains the ADMM candidate; factor-memory-budget failure propagates as failure. The [numerical review](../../atx-engine/reviews/2026-09-20-qp-polish-review.md) compares this with the [pinned OSQP v1.0.0 source](https://github.com/osqp/osqp/blob/v1.0.0/src/polish.c). ATX's initialization, acceptance checks and fixed controls are its own; the command does not invoke the OSQP package.

`allocation_certificates.json` records per-decision timing indices, the frozen risk snapshot hash, raw continuous weights and solver residuals, canonical action/payload instructions, representation diagnostics, constraint measurements and actual fee/turnover accounting. Each proposal also binds its observed-close snapshot hash, source artifact, invalid-unheld security IDs and typed mark classifications. Nonfinite observed prices are JSON `null` with an explicit reason/class, never an invented numeric mark. `available_by_order_submission` remains separate from numerical mark validity.

The full canonical `required_zero_reasons_canonical_order` mask and its digest use bits `1=decision-ineligible`, `2=risk-unready`, and `4=execution-close-unavailable`. `execution_unavailable_count` counts all exact-unheld invalid current marks; `execution_fixed_zero_count` counts additional execution equalities within the original solve union; `required_zero_count` is the deduplicated union count. The older `fixed_zero_count` retains its decision-ineligible union meaning. `fixed_zero_l1_change` is total raw-to-required-zero lifting; its decision/risk and execution-only components are reported separately, with decision/risk precedence on overlapping reasons.

On completion, `report/allocations.csv` records accepted pretrade/posttrade marked dollars, resolved instruction weights, actions and payloads in canonical instrument order. The report also writes the daily ledger, actual trades, final TRI units and liquidity diagnostics. The outer `manifest.json` binds the recipe, source/evaluation/combo/preference IDs and output hashes; it is published only after completion. A replay failure preserves `.pending`, `failure.json` and certified callback proposals without publishing a completed outer manifest. The last callback attempt records decision/execution times, phase, availability and whether a certified proposal/raw vector was actually captured. A failure before a later callback, including a missing held mark, leaves the previous successful callback context and does not invent a failed-candidate record. A helper that returns an error exposes no raw candidate to the stage. Certificates from a failed replay are proposal evidence, not a partial performance record.

The 3 GB setting is conservative array admission plus an overhead reserve, not an operating-system RSS guarantee. It budgets resident panels/replay storage and the complete eligible/risk-ready-plus-held union; the solver rejects an oversized union instead of truncating it. The current stage additionally admits 1,280 bytes per scheduled decision/instrument for retained proposal evidence, 2,048 bytes per instrument for callback workspace, 16,384 metadata bytes per scheduled decision, and escaped identifier copies, using checked arithmetic. It retains only the last callback context plus certified proposal contexts and includes a 512,000,000-byte overhead reserve. Native process measurements remain separate evidence.
