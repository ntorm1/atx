# SP100 Surface Database Production Build Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the production hive-parquet OPRA slice store and per-year fitted vol-surface databases for the S&P 100 universe (plus SPY index leg), 2022-01-01 → 2026-07-25, using the databento loader, with correctness fixes (ET-anchored snapshots, per-month rates, resume-correctness) landed first and validated on small pilots before scaling.

**Architecture:** The existing pipeline is `atx-vol/tools/pull_opra_hive.py` (databento OPRA.PILLAR cbbo-1m, one fixed snapshot minute per session) → hive store `<hive>/date=YYYY-MM-DD/data.parquet` → `atx-vol-surface-db-build` CLI (config + streaming populate into `manifest.atxdb` + `partitions/<date>.atxvsa`) → `atx-vol-surface-db` admin CLI (`verify`/`query`). This plan adds: an SP100 universe file, ET-anchored snapshot support + resume-correctness in the pull tool, a monthly rates table, and a chunked orchestrator that drives pull → build → verify at scale within known memory limits. Everything data lives under `C:/atx-data`; everything code lives in the repo.

**Tech Stack:** Python 3.12 (databento 0.79, pyarrow 18, exchange_calendars, zoneinfo), C++20 CLIs already in-tree (`atx-vol-surface-db-build`, `atx-vol-surface-db`), clang-cl/Ninja via `scripts/atx-build.ps1`, GoogleTest + pytest.

def snapshot_minute_utc(date_str: str, et_hhmm: str) -> str:

    h, mnt = (int(x) for x in et_hhmm.split(":"))
