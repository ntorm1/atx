## 1. What the marginal phase computes, what it gates, and where its inputs come from

**Computation (K6, F-2 verb, `atx-impl/src/strategy_marginal_ic.cpp`).** For every candidate of `--library` (all 52 of
v8.0, `run_marginal_ic` :627-631, :654-655), on each decision row:
- the centred tied rank over the pool's members (:495-498);
- the IC at h 21, and the IC of the rank residualised on 1 + J regressors, with a HAC t (:513 ff.).

The regressors are:
- the pool's combined signal (the parent book's composite, read from the pool files, :494);
- with `--themes`, the parent's theme composites (:499-511; under `theme_standardise` rerank, :457-470).

The theme composites are built only from rows of `--library`. `read_themes` (:188-246) takes every weighted member of
the themes weights file and requires it to be a `--library` candidate (:213-216). That is the refusal:
`themes: pool member accruals is not in --library (its cached signal builds its theme composite)`. The weights file
must also be bound to the pool's library (`library_sha256 == pool.library_sha`, :199) and to the pool's
`composition_weights_sha256` (:195). The verb is built on the premise that the candidate library contains every
weighted member of the pool. That holds for any wave that only adds members, and fails for one that removes or
replaces weighted parent members.

**What it gates: nothing, for both the 7 admission trials and the 8 re-screens.**
- The gate reads only `admission.json` (`scripts/research_cycle.py:1397-1436`). The card in lib-v80 has no
  `--marginal-ic` (card flags `--workers 4 --work-dir build-equity/fit-work`).
- `cycle_verdict.json` copies the K6 rows of the gate's `admitted` ids, the 7 trials (`scripts/cycle_verdict.py:4-5`,
  :100, :107-109). The 8 re-screens' rows would exist only in `marginal_ic.json`.
- Registered: prereg rule 8 (`v8-prereg.md:17`; again at :45): "the report-only columns ic_theta, f_theta and marginal
  IC gate nothing and select nothing". Ruling E-36 (`progress.md:492-498`) and Ruling PM4-9 (`progress.md:866-871`)
  repeat it for library waves.
- Mechanically the phase still blocks the cell: PHASES order fields, check, ref, u, fit, card, **marginal, gate**, w,
  ... (`research_cycle.py:172`; `steps()` :957-969). A failed bounded phase is a HARD-STOP (exit 4), so the gate, w and
  the cell never run.

**Who wrote these keys.**

  `train_combined.json` and `reference_weights` = the parent's fit `composition_weights.json`

## 6. `test_registry_seed_is_the_v71_library`

**What it asserts** (`atx-impl/strategies/test_generate_library.py:120-142`): the registry is exactly the v7.1 seed:
- alpha ids == the v7.1 library's candidates in order (:127);
- every origin is prior (:128);
- tier scores (:129);
- each alpha's prior_sign_source / form / notes / tier rank equals the v7.1 recipe lineage (:131-135; it indexes
  `lineage[a["id"]]`, so a new id raises KeyError);
- `added_in` of named members (:136-138);
- field-table names == the v7.1 library's field declarations in order (:139);
- clocks / origins == the recipe's maps (:140-141);
- themes == the library families (:142).

Any wave registration (E1 rows, add-alpha alphas) breaks it. It failed at :139 after E1; with 15 alphas registered it
now fails at :127.
