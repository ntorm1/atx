## Deviations from brief
1. K-P9-4 argv adds `--role-sha256`, the external pin the exposures verb also takes. The plan does not specify the
   format of `--signals DIR`; it is defined here as `DIR/signals.json`, an index of `{id, payload, payload_sha256}`
   in roster order, because a cache directory alone does not determine which candidates to read or in what order.
2. The factors directory also carries `factor_h21.f64`, the report-only F-3 series. The admission exe reads it for
   `traded_horizon.csv`. The K-P9-4 files are otherwise as declared.
3. The traded-horizon "IC" is defined as the mean of h_k(d) = sum_i q_k(d)_i sum_{j<21} r_i(d+2+j). This is the
   factor-return sense in which ic-shrink reads `train_mean` as IC. `ic_h21_hac_t` is eval::hac HorizonAwareV3 at label
   horizon 21. The PM may rule a rank IC instead; the code change would be confined to the context and to
   `traded_horizon`.
4. `atx-research-admission` is an exe the brief does not name; the migration plan does name it. It is how root
   reproduces `admission.csv` with the C++ screen.
5. `v4-prior-v2` (the turnover_cost check at .08) is implemented beside v4-prior-v1. It is the fitter's second prior
   screen and costs one check.
6. The comparator follows the preflight fix (row 4): the fitter generates the fixtures, the gtests compare the C++
   with them, and the pytest pins the fixtures to the fitter.
7. Sign rule: both predicates are written. `kPm735SignRule = WaveZeroKeptV1` follows Ruling P9 (the Python wave keeps
   sign 0 in wave 1). The exe also takes `--sign-rule`. The rule decides nothing in `admission.csv`; the manifest
   reports its verdict per admitted string. **PM: pick before merge.** The switch is the one constant in
   `sign_rule.hpp`.
8. Era-pooled fits (`--era`) are out of scope: the C++ screen is single-window.
9. The shared `ResearchRole` loader adds the E-10 refusal of delisting-returns roles. The fitter does not check this,
   but the runner already refuses such roles for signals.

## Open risks
- First compile happens at root. The code was written to clang-cl `/W4 /permissive- /WX` and to the 100-column limit,
  and was not built.
- The `factors` Debug runtime on a full role (about 1,000 decisions x 100 candidates) has not been measured. The TU
  has private /O2 for this reason.
- `python_float_repr` assumes the shortest digits from MSVC `std::to_chars` (Ryu) equal CPython's dtoa mode 0. Only
  the placement logic was checked against `repr`.
- `screen.cpp` and `traded_horizon.cpp` use `eval::hac::detail::{mean_of, lag_cross_product}`. This namespace is
  internal to the header.
- An FMA-contracting preset (rel-avx2) could move fixture bits. All fixture comparisons are 1e-12 except the CSV
  writer test, which formats the fitter's own values.

## Ledger candidates
- The fitter's `newey_west_t` keeps the declared lag L in the Bartlett weights 1 - l/(L+1) when n - 1 < L.
  `eval::hac::mean_inference` clamps the lag, so for n <= 5 the two give different t values (example: -59.40 vs
  -48.5). The C++ handles this as HacMethod::FitterNeweyWestV1.
- `admission.csv` cannot be byte-reproduced in C++ because numpy reduces pairwise and through BLAS. On 2^-24-quantised
  synthetic rows, sequential C++ sums tie the fitter within 3e-15 relative, against the Ruling P12 tolerance of 1e-12.
- Python's `repr(float)` uses the shortest digits, in exponent form iff decpt <= -4 or decpt > 16 (Python's position
  of the decimal point in 0.ddd x 10^decpt), with a two-digit minimum exponent. The C++ spelling is `to_chars`
  scientific plus the placement in `admission_csv.cpp`.
