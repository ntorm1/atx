### Cache statement (contract section 4)

The list changes no signal-cache or IC-result-cache key or entry bytes: a listed member is evaluated
(VM or verified hit) and its real signal is stored under its unchanged key before the blanking; its
IC result is neither read from nor written to the IC-result cache (both scopes, `--label-terminal`
included), because those entries key on the real signal bytes and the run scores the blanked
signal. A cache dir shared by runs with and without the list therefore serves each only entries
whose use leaves its bytes as on a fresh cache. Proof: `SharedCacheNeverCrossServes...` (cold run
without the list; warm run with it: listed member signal hit, IC miss, its IC entries' bytes
unchanged, outputs equal a fresh-cache run with the list; warm run without it: all IC hits, outputs
equal the cold run; cache bookkeeping aside).

## Equivalence (contract section 5): what is proved

`expect_absent_equivalence` (`strategy_ic_runner_test.cpp:5254`): the library's listed members read
a field `gate` no other candidate reads (DSL `(DSL) * gate`; gate a positive multiplier at scale 1,
NaN at scale NaN). Run 1: the pass with the list on I. Run 2: the same pass without it on I' (the
same fields paths, gate NaN). Fresh cache dirs (when the case uses a cache). Compared: every file
the pass publishes (same file set, >= 10 files; with `--save-combined`): binary payloads byte for
byte; text byte for byte after substitution; `summary.json` and `*_candidates.jsonl` after dropping
the excluded keys on both sides. A third run (without the list on I) must differ in both roles'
`_combined.f64`, so no case is vacuous.

- Per-member rows hold as stated: the blanking precedes IC scoring, so a listed member's IC rows,
  daily series and TRAIN orientation (sign 0) are I''s. The equivalence is proved over every file.
- Excluded keys (contract): `wall_seconds`, `stage_seconds`, `hash_seconds`, `candidate_cache`,
  `signal_cache`, `ic_result_cache`, `ic_missing_exit_v1_result_cache`, `absent_members`.
  `verify_bytes` and the field-load counters are compared (equal on fresh caches).
- Substitution (not in the contract's list; for the PM): I' differs from I in an input pin by
  definition, the gate fields manifest SHA-256 and the gate payload SHA-256 per role, which the
  recipe, summary, orientations and combined manifests record; and so in the hashes over those
  records (`recipe_sha256`, `orientation_recipe_sha256`, `orientations_artifact_sha256`, each
  role's combined `manifest_sha256`). The test substitutes I''s values by I's in run 2's text;
  each substituted hash's preimage file is itself compared, so no flag-caused difference can hide.

## Deviations

1. Semantics live in `score_role`, not in `IcComposition::add` / `add_standardised` (the brief's
   scope line; the dispatch's "per-date skip" in the S-3 helper). Contract section 4 leaves the
   route to the C++ lane and D3W's review "For ABS" names this route ("blank that signal before
   scoring, so the equivalence holds over every file"). Blanking at one place makes the composition
   input byte-identical to I''s, so every rule (redistribute, standardise, residualise, schedules,
   sleeves, hedge, mom-volman, v3 rows) applies its own missing-member rule unchanged, and the
   per-member rows hold; a composition-level mask would be a second mechanism with its own proof per
   rule and would leave the member's IC rows wrong. No per-date skip is needed (every date); S-3's
   `Impl::weight_at` is where one would go.
2. A listed member is still evaluated (VM or cache): field loads, verified bytes and cache entries
   stay I''s, and the shared cache keeps the member's real entry. Cost: one VM evaluation per
   listed member (12 in P9). Skipping it is a P10 option (it would move the field-load counters).
3. `--plan-only` / `--cache-report` validate the list but print nothing new (the contract names
   summary.json only).
4. The list is checked after the library and composition weights (still before any payload or
   output); run_ic refusals exit 1, the repeated flag exits 2 (argv level, as the other parse
   refusals).
