## Identity and clock fields

| Input | Documented usable fields | Limitations for D1 |
| --- | --- | --- |
| Insider `SUBMISSION.tsv` | `ACCESSION_NUMBER` primary key; `ISSUERCIK`, `ISSUERTRADINGSYMBOL`, `ISSUERNAME`, `DOCUMENT_TYPE`; `FILING_DATE` and `PERIOD_OF_REPORT` use `DD-MON-YYYY`. UTF-8, tab-delimited. | A filed issuer-symbol observation, not a complete validity interval or class identifier. **No acceptance timestamp** in the documented table. Event/report date cannot substitute for public availability. Preserve amendments. [Schema, §§3–5.1](https://www.sec.gov/files/insider_transactions_readme.pdf) |
| FSDS `sub.txt` | `adsh` accession key; `cik` registrant, nullable `sic`; `filed`=`yyyymmdd`; `accepted`=`yyyy-mm-dd hh:mm:ss`; `instance`, `nciks`, `aciks`. UTF-8, tab-delimited, lowercase header. | `accepted` is sourced from EDGAR. No dedicated ticker field: `instance` filename may begin with a ticker, so its prefix remains a candidate. Co-registrants need explicit handling. SIC describes business, not security type. [Schema, §§4–5.1](https://www.sec.gov/files/financial-statement-data-sets.pdf) |
| Historical submission header | `<ACCEPTANCE-DATETIME>`, accession, filed date, and role-specific CIK metadata. | Join exact accession to the Insider issuer record; do not infer issuer CIK from accession prefix, which can identify an agent. Header alone does not establish security-line type. [Timestamp definitions](https://www.sec.gov/about/webmaster-frequently-asked-questions), [archive paths](https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data) |
| EDGAR daily/quarterly indexes | CIK, company, form, filed date, filing path; indexes available from 1994Q3. | Discovery only: no ticker or acceptance timestamp. The path locates a submission/header. [Index documentation](https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data) |
| Submissions API | CIK-addressed filing history; current company ticker/exchange metadata; older-file references with date ranges. | Current main responses and nightly bulk mix eras. Current tickers are not dated identity evidence. The API overview does not specify the acceptance field's detailed schema; the local normalizer described in the brief retains it, but exact pre-2020 records still need validation. [API documentation](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) |

The SEC FAQ documents header acceptance time as EST, `HHMMSS`, and explicitly provides no timestamp for first availability on sec.gov. Preserve raw time and source; specify timezone/DST interpretation and dissemination/session lag before strict use. Do not relabel a naive timestamp UTC or a modeled filed-day hour verified. Acceptance and actual first-public availability remain distinct. [SEC timestamp FAQ](https://www.sec.gov/about/webmaster-frequently-asked-questions)

Archive vintage matters: the FSDS listing records December 2024 reprocessing, including a NUM layout change. The Insider listing records a 2025 refresh of 2023–2025 files adding `AFF10B5ONE`; this does not prove the column exists in pre-2020 files. Capture actual member headers and source hashes, with vintage-aware parsing. Quarterly posting boundaries may defer late filings to the following archive; a missing final-quarter row must remain unresolved without separately bounded pre-2020 evidence. [FSDS notices](https://www.sec.gov/data-research/sec-markets-data/financial-statement-data-sets), [Insider notices](https://www.sec.gov/data-research/sec-markets-data/insider-transactions-data-sets)
