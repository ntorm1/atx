## Minimal adapter boundary

Use a callable contract, rather than one base class per subsystem:

```text
Case = immutable fixture + canonical axes + fixed recipe/split/seed
Cut  = session index + explicit decision/availability timestamp + clock policy
run(Case, RunRequest) -> Result<Snapshot>
Snapshot = ordered typed Records + read/execution clock evidence
Record key = component, output kind, decision/realization key, instrument/model/fold key
Record value = explicit shape, validity/eligibility bytes, scalar/array value bytes
Mutation = id + apply(Case copy, Cut) + changed-input/visibility receipt
check(base, mutant, Cut, descriptor) -> first differing key/shape/byte or clock violation
```

The fixture owns all borrowed spans until a run finishes; each run has fresh state and the same RNG seed, split, execution settings and algorithm mode. Do not copy raw C++ struct memory (padding/pointers), hash unordered iteration, stringify floats or canonicalize NaNs. Serialize named scalar fields and contiguous arrays with fixed integer widths/order, then compare exact lengths and bytes, including signed zero, NaN payloads, masks and row keys. A digest is a receipt, not a substitute for comparison or a useful failure location. Missing/extra protected records, a shortened result, mismatched schema, unexpected error or zero eligible records fail. Declare intentional empty/warmup cases separately and require a nonempty mature case for each adapter.

The existing `validation/bias_audit.hpp::check_no_lookahead` is not this contract: it compares floating values with `!=` over the minimum returned length. That can equate signed zeros, reject identical NaNs and silently omit missing outputs. Implement the planned X1 helper with strict geometry/bytes; this brief does not authorize a general rewrite of that older helper.

## Cut and visibility semantics

1. **Primary experiment: same shape, changed unseen information.** Keep the complete date/instrument axes, decision schedule, warmup, folds and visible input bytes fixed. Change each applicable future channel separately, then jointly: prices/missingness, adjustment events/revisions, fundamentals/availability, membership/identity versions and labels. The receipt must prove that at least one inaccessible input changed and that visible inputs did not. Pass the mutated full input through the real production boundary: pre-truncating every caller input would hide year-union/full-panel defects. A production API that explicitly takes an as-of slice may receive that slice, but its production slicing path must also be covered; slicing-only invariance is not proof of causal estimation.
2. **Availability is separate from event/session date.** `panel_artifact.hpp` declares Unix-nanosecond session labels as `session-label-not-availability`; `alpha::Panel` alone has no time axis. Adapters must bind an explicit clock, never infer historical availability from a manifest timestamp or session label. `data/dataset_schema.hpp::DateKeyEncoding`, `data/align.hpp::align_onto` and `clock/sim_clock.hpp::is_visible` supply the existing conventions. Respect encoding, calendar-day PIT delays versus session offsets, and inclusive `available_at <= decision_at`; an already aligned dataset must not receive its delay twice.
3. **Backdated revisions remain future inputs.** A future filing/identity confirmation or corporate-action adjustment can describe an earlier effective date. Mutate the later-available version/payload while holding the earlier visible version fixed; resolve through the production as-of join. Do not backfill the new fact into earlier decisions. D1/D5 owns identity interval/availability semantics; X1 consumes that contract, including unresolved identities rather than guessing a ticker join. Changing a clock across the visibility boundary belongs to a separate boundary-response case, not an invariance case falsely claiming its visible inputs stayed unchanged.
4. **Secondary prefix experiment:** truncate at declared cut boundaries and compare the same protected records only when the production contract preserves those records' roles. Do not recarve WF folds from the shortened panel length. Replay's final row is valuation-only, so making an originally tradable cut row terminal is not an equivalent experiment; keep that row interior with the documented boundary fixture, or use the primary same-shape mutation. Pin absolute training/validation windows and stable instrument keys; never use `min(lengths)` to hide the discrepancy.
5. **Output scope is semantic, not a filename prefix.** Compare signals, selected features/models, weights, orders and accounting states at their actual decision/valuation clocks. A full-run SR, bootstrap interval or final mining report is known at its latest consumed observation and may change. Obtain an as-of aggregate by rerunning the production aggregation on the declared mature prefix. Future input hashes, source SHA, temp paths and wall timings are separate provenance, not economic output bytes; list these exact exclusions in the descriptor while still validating artifact parent/hash integrity independently.

## Label maturity and execution clocks

Never require a forward-return label anchored before the cut to remain unchanged when its endpoint is after the cut. Protect features and predictions at the anchor; protect realized labels/IC/PnL only after their endpoint and availability. `eval/cross_section_ic.hpp` defines entry `d + execution_delay`, endpoint `d + execution_delay + h`; `stage_equity_mine.hpp::score_signal` defines held-return endpoint `d + delay + 1`. Do not transfer one convention to the other by name alone.

`learn/feature_matrix.hpp` carries `row_date`, `row_inst`, `Y` and `label_horizons`; `label_matured(r,H,t,e)` enforces `r + H <= t - e` without overflowing. Its empty horizon metadata is unannotated, not a zero horizon. At this source `src/learn/feature_matrix.cpp::build_features` does not populate `label_horizons`; L1 owns that propagation. X1 must surface the missing prerequisite or use an explicitly annotated synthetic adapter fixture, never claim the live dataset producer has already supplied it. Test exact-boundary and one-before maturity and declared availability lag. Do not double-add execution delay when a producer's horizon already describes the endpoint.

For CPCV, fold exclusion is an additional constraint: a fold's held-out labels must not alter that fold's preprocessing, selected checkpoint, trained artifact or OOF predictions even when those labels are chronologically mature. Freeze the fold membership and inspect `LearnFitTrace`. CPCV training may use later dates in other permitted folds; passing fold isolation is **not** evidence that an OOF model was historically deployable. Separately qualify a chronological deploy model with the as-of maturity gate.

Future-mutation invariance alone cannot detect every delay-0 execution assumption. The harness also checks the declared execution clock: the corrected default cannot fill the signal-close decision before the next eligible observation. A planted delay-0 fill fails this timing assertion even if its numerical computation is future-invariant. Explicit same-close legacy diagnostics are labelled as such and cannot satisfy corrected-default acceptance.

## Discriminating controls and postimplementation acceptance

Use deterministic synthetic fixtures only; freeze visible inputs, cuts, nondegenerate exposures and seeds. The initial planted-control set must detect all eight below. Prefer an existing versioned legacy route; otherwise plant the incorrect read in a test-local alternate adapter. Flipping an output bit only proves the comparator and does not count as a planted economic leak.

| Required control | Observable failure |
| --- | --- |
| Year-union membership | A name admitted only later changes an earlier eligible cross-section under the planted union mask. |
| Adjusted-level ADV | A later-available adjustment revision changes historical adjusted-price liquidity/capacity under the planted recipe; raw observed dollar volume remains invariant. Keep the earlier raw history fixed. This does not waive W2-A3's wider basis lint. |
| Delay-0 return/execution | Same-close execution violates the explicit earliest-fill clock; delayed labels/realized PnL are timestamped at their real endpoints. |
| Full-panel variance | Future return perturbations change an earlier risk model/target under `DiagRiskRule::WholePanelV1`; the expanding default is invariant. |
| Test-fold checkpoint | Held-out-label mutation changes a fold artifact/checkpoint under the existing legacy learner control; corrected artifact and predictions stay identical. |
| Last-date ADV | Altering future raw price/volume changes an earlier participation bound/target in the planted end-of-panel reference path. |
| Immature-label selection | A label anchored before cut but ending after it changes selected features/model only in the unfiltered alternate path. |
| Future-available revision | A later filing/identity/fundamental version with an earlier effective date changes an earlier feature/membership decision when joined on effective date alone. |

Also register the existing future-last-print replay control and VM future-window read where applicable. Require the corrected production run to pass and the paired planted route to fail on the **same fixture/cut**, with the first differing protected record or clock violation recorded. Preserve existing W0 proof obligations; a legacy control passing because the fixture has no sensitivity is a failed qualification.

After implementing adapters, run only owning targets first, then the integration receipt. Include cuts before/at/after availability, at maturity/embargo boundaries, warmup/gaps/reappearance and one active trade/constraint. Repeat the same input to separate nondeterminism from leakage; test deterministic worker/chunk variants only where the component promises them, without loosening the byte requirement into a numeric tolerance. Record source/rule/fixture hashes, exact test target/filter, tested adapter/subpath denominator, protected-record count, changed-unseen count, control result and missing/unrun reasons. A green X1 gate requires all eight initial adapters plus every registered active subpath and all eight planted controls; no build, runtime, historical-data coverage or acceptance is claimed by this preparation.
