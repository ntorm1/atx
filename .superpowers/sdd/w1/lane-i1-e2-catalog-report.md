## Implemented consumer and accounting

`eval/trial_epoch.hpp` declares a move-only private-implementation catalog; `src/eval/trial_epoch.cpp` owns the format, locking, validation, indexing and durable append. Root must register that one new production CPP. `prereg.hpp/.cpp` preserve typed prior prereg-file SHA, prior family-configuration SHA and prior trial ID. Default parsing retains the original same-family requirement; explicit E2 permits renamed display metadata only subject to the catalog's exact prior-cell proof.

Actual `equity-ic` opts in with `--ic-trial-accounting-rule epoch-e2-v1`, `--ic-epoch-catalog`, and a mandatory lowercase SHA256 `--ic-epoch-anchor`. Runtime preregistration is required. `legacy-ledger-v1` remains the default and refuses stray catalog/anchor settings through the root validator. The actual stage calls the same validator directly. E2 and the frozen JSONL ledger must be distinct paths; the old ledger schema/count remains unchanged.

For each preregistered family/horizon/forward-variant/restriction, a cell hashes canonical DSL, explicit sign, horizon, variant, restriction, effective recipe digest and the existing bootstrap signal/horizon stream indices. The recipe is an explicit whitelist: context/evaluation payload and ordered-axis hashes, window, membership, observation basis, liquidity admission, common maximum horizon, estimator/bootstrap/tie/version choices, cost constants, numerical terminal evidence including unevidenced flags, and ex34 mark support. Display names, family ID/theme, checkpoint, output path, whole prereg digest, executable SHA and source prose are excluded from the numerical key. Output path and exact prereg hash instead bind the separate attempt token. The reference baseline/combo columns are not represented as new preregistered family trials.

Bootstrap streams currently depend on positional indices: moving a family or changing its within-family horizon index can change sampled intervals, so this legitimately changes the numerical cell. Changing the registered maximum horizon changes the common sample and therefore its recipe. Alias-only changes at the same effective indices do not create cells. The full prior family hash remains lineage proof, separately from the alias-independent cell key.

`known_unique_cells` counts distinct numerical cells in this catalog; `measured_declarations` counts all reserved cells including repeated runs. Verified retained references must identify a prior reservation with matching exact prereg bytes, prior family hash, prior trial ID, and each exact numerical cell. A prior failed/incomplete declaration still counts; it supplies declaration lineage, not successful numerical evidence. A declaration labeled new can repeat an already-known cell, without inflating unique N. Unknown or mismatched retained proofs fail before reservation/VM. Attempts/completed/failed/incomplete are separate counters. Declared-new N and the legacy measured count retain their existing meaning.

## Failure and identity protocol

Each event is framed as 8-byte magic, 8 decimal length bytes, canonical JSON, 64 lowercase SHA256 bytes and newline. The JSON binds epoch, schema, sequence and prior head. Each operation takes a fail-fast exclusive OS file lock over the existing handle, scans/verifies all bounded events and requires the exact expected external head. No adjacent mutable sidecar is trusted. Sixty-four zeros permit an empty catalog only; reopening an existing nonempty catalog with zeros or a stale head fails before a new reservation.

The current consumer serializes catalog mutation through explicit head handoff. It does not silently merge another writer's events while a handle is running: an intervening valid append makes that handle stale, and finalization then requires reopening with a trusted current anchor. Catalog proof means correspondence to hash-bound declarations, not authentication of a caller. The actual stage computes prereg/family digests from the same validated bytes; generic API callers retain that input-provenance obligation.

Append validates and allocates its next index before writing, then flushes and uses `_commit`/`fsync` before acknowledging the event. A partial write or failed sync poisons the handle. Torn/checksum-invalid frames fail closed without truncating or repairing any bytes. A valid pending reservation survives process death and stays counted. Filesystem/power-loss guarantees beyond the OS sync contract are not claimed.

Exact token+payload repetition returns the existing reservation without appending or incrementing; a changed payload under that token fails. Exact repeated terminal status/result proof is similarly idempotent; conflicting terminal state fails. The stage refuses VM reruns of any already-reserved token and requires a fresh output attempt. Catalog idempotency is a recovery property, not a route to uncounted experiments.

E2 reservation occurs before the family VM and before the legacy pre-line. Every guarded post-reservation exit—including failure to append that legacy pre-line, family VM refusal, numerical/output failure and legacy terminal failure—goes through E2 terminal finalization. If finalization cannot be written, the durable pending reservation remains counted. The stage publishes `epoch-reservation.json`; request/summary/immutable manifest bind its reservation head. The terminal binds the completed manifest hash or a precise failure receipt. `epoch-anchor.json` is a separate export of the later head and counts; it must be trusted/exported separately. The immutable manifest is never rewritten to include its own terminal head. E2 `.pending` remains until terminal and anchor publication finish. A terminal may be committed while subsequent anchor publication fails; the stage then reports an error and preserves incomplete publication rather than undoing the catalog.

## Bounds and remaining qualification

Hard ceilings are 64 MiB file, 4 MiB event, 4096 attempts, 65536 measured cell declarations, 2048 cells per attempt, 4096 DSL bytes and 32 KiB canonical numerical recipe. Default working admission is 256 MiB, with conservative 64-times encoded JSON scratch and explicit retained-index charges, including old/new indexes coexisting during refresh/transaction. These are allocation-admission models, not measured RSS claims. E2 inline terminal recipes refuse more than 128 terminal events rather than silently omitting support. Source stage memory reserves remain independent; large-scale memory qualification is pending.

Five new `TrialEpoch.*` cases cover pending recovery/idempotency, exact lineage and alias dedup, numerical mutations, stale anchors/torn preservation, and malformed/bounded admission. Two prereg tests cover separate prior proof and parser/direct-stage policy guards. Two actual synthetic stage tests cover completed manifest/reservation/terminal binding plus retained alias, and both legacy-pre and family-VM failures. Fixtures were written after implementation and are unrun. Suggested owning registration: `atx-engine/tests/eval/eval_trial_epoch_test.cpp`; existing impl prereg/stage IC TUs are extended. No broad suite or numerical performance run is requested by this report.

This is a bounded E2 declaration catalog with one actual opt-in consumer, not completion of original I1/E2 acceptance. Historical cp14–22/L9/L10 imports are absent and their cumulative unique total is unknown. No calendar P&L/sketch is invented or attached, no statistical registry is silently concatenated, and cluster-N/DSR coverage remains unavailable. Mine/discover/combine and other stage counts are not yet migrated into this catalog. All-stage manifests, history reconciliation, epoch import tooling and an explicit calendar-compatible evidence attachment remain follow-on work. No alpha/tradeability or production-scale claim is made.
