### Issues — Critical / Important / Minor

Critical: none.

**Important I1 — Absent/duplicate daily bars become finite qualified period returns** (`_factor_sources.py:76–89`, `_factor_native.py:227–248`, `:305–324`). issuer_period_sql compounds observed bars without checking the required session grid or uniqueness of (security_id,session_date). A qualified line with only March 1 return .10 in a two-session March 1–2 period emits .10 instead of NULL. Duplicating its March 1 .10 bar emits .21. The fixture's independent quality flags remain true in both cases. signal_history similarly counts present months without checking complete daily support; historical BAB market construction inner-joins prices and can omit a missing eligible line from that day's market weight denominator. Price-parts setup can concatenate overlapping history/current files without a uniqueness policy. The monthly/daily BAB call also constructs its legs from current surviving eligible rows rather than preserving a missing formed member as missing. Fix: define and validate the complete eligible line/session grid, explicit overlap/delisting treatment and missing-return behavior before compounding or weighting; reject duplicates and preserve missing eligible weights. Regressions should remove one bar, duplicate a bar, overlap price source parts, remove one member from an otherwise populated issuer/market/BAB leg and verify no renormalized finite return appears. Missing-price/source cases must remain visible exclusions/failures, not silently shortened return windows.

**Important I2 — Risk pack does not implement its declared primitive timing and issuer-ME basis** (`_factor_sources.py:94–115`, `_factor_native.py:522`, `:551–567`). risk_primitives_sql selects universe ME for the current day, while cap qualification is selected for the previous session; size/value then use that current line ME. It neither uses the audited lagged ME nor sums multiple lines into the frozen configuration's issuer ME. Two share classes therefore receive different size/value inputs for the same issuer. Independently, borrow selection checks cutoff_utc only and emits fields without enforcing the selected si_to_io/si/FTD/threshold availability clocks. A tiny fixture with March 1 parent cutoff and March 4 individual field clocks emits si_to_io=7 and si_shares=100 for March 2. The final projection drops those clocks and keeps the values. Fix: bind ME and its qualification to the same strictly visible source observation, consolidate issuer ME before deriving issuer styles, and enforce each primitive's effective component clock (or verify an equivalent producer invariant before accepting it). Include cutoff-boundary/future-component mutations, current-day ME mutations and multiclass issuer tests. This is a GC1/source-basis defect, not a waiver for the known share discrepancy.

**Important I3 — Resume identity omits selected outputs and adapter semantics** (`_factor_native.py:57–101`, `:342–343`, `:504–505`; `_factor_io.py:34–51`). setup returns source manifest hashes, but omits files selections, price-part selections and RF adapter/frequency_files mappings. Generation identity adds config/code, not the full normalized source specification. Changing selected files or an adapter mapping under the same exact manifest therefore produces different source views with the same generation token, and done() reuses the previously completed output bytes. The old payload can subsequently be certified under a changed source selection. Fix: include exact selected member identities, normalized adapter parameters and complete release/audit bindings in generation identity. Add a two-run fixture that changes selected members/mapping without changing the source manifest hash; the second run must compute a distinct generation or refuse the mismatch. Output hash validation alone does not identify which input relation was used.

**Important I4 — Own factors can be stale relative to the risk release** (`_factor_native.py:489–501`, `:574–575`). native_risk accepts an exact factors manifest/output hash and matching config, but never requires its producer input_manifests_sha256/release identity to match the final v11/universe/price bindings used for this risk build. setup_check rechecks the current sources and rechecks the old factors snapshot separately; both can be valid snapshots of different releases. The positive risk fixture even constructs a factors manifest with no producer lineage and this guard accepts it. Fix: require complete own-factor source/config/code lineage and equality of the relevant final release/source identities before joining, then recheck before publication. Regression: same formula config, individually valid old factors, changed universe/std/price release; fail before risk publication. This is plan-mandated R14/R9 descendant-refresh compliance, separate from absent real producer evidence.

**Important I5 — EG/BAB audit joins multiply or suppress legitimate audit vintages** (`_factor_native.py:144–151`, `:181–186`, `:302–315`, `:522`). formation_issuers/issuer_period use the latest visible audit row per line/date, but EG fiscal_me and training ME directly join all visible audit rows. Two successive independently verified audit rows for the same line/date count its ME twice. Tiny fixture: one issuer, ME=100, AT=100, zero debt gives log_q=0 with one audit; adding a second visible qualifying audit changes log_q to ln(2)=.6931471805599453 without any price/accounting change. native_betas also joins all audit vintages; risk cap bool_and consumes all old rows, so an old failed audit can continue suppressing a later resolved one. Fix: share one deterministic latest-visible audit relation per key across every consumer, rejecting conflicting equal-clock records. Test repeated positive audits, failed-to-resolved and positive-to-revoked vintages, and strict cutoff invariance. The economic-source audit must remain independent; this fix must not certify currently unresolved sources.

**Important I6 — Full required coverage denominators are not represented by the gate** (plan-mandated GC3; `_factor_native.py:582–587`, `_factor_sources.py:94`).
