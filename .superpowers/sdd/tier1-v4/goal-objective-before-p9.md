Goal: Bring atx-db’s alpha feature panels to production quality through repeated, evidence-driven improvement, ending with a reproducible release that atx-impl can load and use.

Work autonomously through diagnosis, implementation, testing, rebuilding, independent review and consumer acceptance. Complete authorized work without repeatedly asking permission. Do not claim predictive quality or production readiness without measured evidence.

1. Establish the current baseline

Read AGENTS.md, the Tier1-v4 plan, gap analysis, progress ledger, task reports, evaluation addendum, source manifests and atx-impl’s consumer contract.

Treat historical status reports as leads; verify current artifacts and hashes. Distinguish code implemented, data published, quality gates passed, predictive evidence established and consumer delivery accepted.

Prefer codebase-memory MCP tools for code discovery when available.

Reconcile the separate gold and golden_panel workflows into an explicit release/dependency plan. Preserve concurrent work and foreign-owned files. Do not start competing builders or replace another session’s published outputs.

2. Define acceptance before changing results

Create a versioned readiness matrix with each requirement, threshold, measurement command, evidence artifact, dependency and status.

Preserve existing acceptance thresholds. Separate:
- Data correctness and point-in-time integrity.
- Coverage and feature construction.
- Statistical predictive evidence.
- atx-impl integration.
- Operational reliability.

Freeze evaluation choices before measuring returns. Do not weaken a gate, change a denominator or omit failed candidates to obtain a PASS.

3. Run a recursive improvement loop

For each iteration:
a. Select the highest-impact unresolved failure.
b. Reproduce it and trace its cause to original source evidence.
c. Implement the smallest general correction.
d. Add meaningful regression tests for the failure.
e. Rebuild affected dependencies under memory limits.
f. Rerun affected acceptance checks.
g. Have an independent reviewer inspect the change and evidence.
h. Record before/after measurements, hashes, remaining defects and the next action.

Use bounded implementation/review agents where available, with explicit file ownership and no overlapping writers. Follow existing review-cap rulings. If a failure requires a missing upstream producer, implement that dependency while keeping the original acceptance failure open.

Prioritize correctness and source recovery before expanding the feature library.

4. Repair and qualify the data foundation

Address the current universe, fundamentals, ratios and announcement-clock failures using the latest reports.

Verify historical membership, delisted securities, security/issuer mapping, share-class and ADR basis, splits, units, currencies, filing vintages, fiscal durations, quarterly/annual reconciliation and strict information cutoffs.

Preserve unknowns as missing with reason codes. Never invent zero values, publication clocks, terminal proceeds or source support.

Quarantine unsupported note/segment fields and ambiguous extraction results. Admit only explicitly qualified features; publish every exclusion and its coverage impact.

5. Build and evaluate useful feature families

Prioritize:
- Liquidity and trading-cost inputs.
- Value, profitability, accruals and investment/growth.
- Momentum and residual risk.
- Announcement-based earnings and guidance.
- Ownership, short activity and other families when their sources qualify.

Publish raw values, normalized scores, controls, quality masks, source lineage, clocks, units and missingness policies. Keep labels physically separate from features.

Follow the existing Tier1-v4 evaluation addendum, including its predeclared candidate directions, 5/21/63-session horizons, IC, quantile spreads, overlap-aware uncertainty, yearly stability and multiple-testing correction.

Keep all return-based evaluation and complete forward-label windows strictly before 2023-01-01. Do not inherit another workflow’s later-period authorization. Preserve consumer seals.

Any new feature search must use an explicitly designated development period with purging/embargo. Track all trials. Never recycle evaluated data as untouched holdout or tune features against confirmation results.

Distinguish statistically supported signals, exploratory candidates and controls. Report turnover, liquidity/capacity exposure, cost sensitivity and incremental contribution against the existing signal set. Gross significance alone does not establish net profitability.

6. Deliver and verify the consumer release

Produce versioned panels and a machine-readable field registry with pinned code, source manifests, schemas, universe, date coverage, formulas and evaluation configuration.

Export to atx-impl’s exact date/security axes and binary contract. Verify ordering, uniqueness, complete membership alignment, NaN behavior and availability timing.

Run a real atx-impl acceptance load and representative downstream smoke workflow. Record exact commands, artifacts and results.

Verify deterministic rebuilds, bounded memory, atomic publication, restart/resume behavior, stale-input rejection and rollback. Use existing guarded data-job limits of at most 1 GiB; avoid unbounded scans and duplicate heavy jobs.

7. Finish with evidence

Deliver a concise release report and atx-impl handoff containing:
- Approved fields and intended uses.
- Excluded fields and reasons.
- Coverage and point-in-time audit results.
- Full predictive results, including failures.
- Consumer acceptance evidence.
- Reproduction, refresh, monitoring and rollback instructions.
- Remaining limitations and precise release status.

Continue improving while actionable engineering work remains. If predictive gates fail, retain that failure honestly and pursue justified source or development-period improvements without contaminating confirmation evidence.

Mark the goal complete only when all required release gates pass. If final certification requires unavailable independent validation, source rights or an owner decision, complete everything else and identify the exact remaining dependency.
