# Incremental efficiency options v1

Read-only engineering analysis; no implementation or actual job. Frozen producers, R23 runtime, economics, full native replay, actual-byte/source/code admission and existing whole-task caps remain binding. Task17 owns R26 integration fixes. This document is a design proposal, not qualification, scheduling permission or a gate PASS.

## Recommendation

Smallest immediately usable step is the existing reviewed R23 `fund_release_runtime.build(...selected=...,max_new_batches=1)` under unchanged resource/host admission, with independently admitted extraction receipts and all native checks. Its minimum admitted quantum is one whole original batch, not one issuer. Do not blindly relaunch a held batch just because it has output files. In parallel, keep read-only code/interface analysis, docs and review preparation moving; do not overlap source scans or extra data jobs with the single guarded actual slot.

Highest-impact next design is a NEW private issuer-checkpoint/streaming assembly helper in controller-authorized integration ownership, calling unchanged native issuer/SQL kernels. It can reduce Python batch accumulation and preserve completed issuers after interruption, but cannot seal an original unit until the unchanged whole-batch replay and receipt/population comparison succeed. Its feasibility needs focused synthetic equivalence review before any actual use; it does not reopen or edit frozen producers. For13F, exploit the already authenticated persistent SQLite directory and batch multiple bounded partitions into one authenticated archive session, retaining independent partition commits and refusing interrupted partitions. A new session-taking inventory adapter is required; the existing inventory function always reopens the archive.

### Native memory boundary and available smaller kernels

`fundamentals._base_sql(src,cik_filter=''):632` is already issuer-filterable and performs native concept/forms, clock, class shares, positive sums and label joins. `_issuer_extras(con,base)` collects batch SIC/pre-flags/clock basis; `stream_issuers(con,base)` fetches50,000-row chunks but retains a whole issuer's fact history. `fund_items.issuer_events` owns unchanged per-issuer fiscal/vintage/FX/structural/missingness arithmetic and counters. `_HistoryWriter` buffers100,000 history rows. `process_batch:777` retains **all batch events**, emitted accession set and SIC rows, then creates full event/catalog Arrow tables. DuckDB256MB does not cap those Python/Arrow objects. One pathological issuer can remain large even after batch accumulation is removed.

Thus an unchanged connection-taking **issuer derivation kernel exists**, but an unchanged issuer-level release admission API does not. Splitting time windows is unsafe: issuer_events depends on complete chronological fiscal/vintage history. Split only on complete CIKs and retain every original CIK, raw concept row, duplicate/reject/filter counter and accession. Arbitrary reduced source batch Parquet cannot be passed off as an original batch or independently admitted extraction. No clone/monkeypatch/global override or new economics are needed/allowed.

### Proposed bounded private cache (not yet implemented/approved)

Bind original complete batch identity and independently expected global snapshot/code/contract/runtime/extraction admission. Obtain ordered complete CIK inventory from original source via native SQL and freeze exact expected count. For each CIK, use native `_base_sql` with safe exact CIK filter, `_issuer_extras`, `stream_issuers` and unchanged issuer_events; persist events/history/SIC and all deterministic counters in a private immutable attempt with independently reproducible source/CIK/clock identities. Seal a CIK checkpoint only after bounded native replay/typed multiset comparison and before/after actual pins. Retain failed/partial attempts; never interpret their files as success.

Assemble native batch events/catalog/history/SIC via bounded writers and deterministic complete CIK concatenation, retaining exact schemas, nullability, duplicates, all original counts and SIC carrying per issuer. Compute complete-batch native filter_counts once using original SQL (summing filtered CIK counters is acceptable only after equivalence proof including synthetic class/pos/label branches). The native receipt's source/FX/code/counters/Cik/fact/event/history fields must match original `receipt_semantics` exactly except already excluded seconds/created_utc. **Before admission run unchanged whole-batch `_replay` and validate_payloads(EXCEPT ALL both directions), exact receipt semantics and normal frozen seal/public protocol.** New finer caches remain private progress; they cannot become final admitted batch records through invented receipt shape.

Important limitation: unchanged frozen `compute_new` does not accept assembled private caches and reruns whole batch itself. A new owned orchestration boundary would need explicit controller authorization and independent proof that it constructs exactly the existing admitted-unit schema/start provenance and still calls unchanged full validation/replay. This design cannot simply be injected into the approved R23 runtime or claim new usable progress today. Even after cache support, final native full-batch replay still retains full events and may remain the memory bottleneck. If that alone cannot fit, smaller final validation execution quantum is genuinely unavailable under current frozen API; do not silently replace it with per-issuer checks or relax memory caps. Route a concrete structural blocker for controller ruling.

Proof required: complete issuer set/zero-row issuer behavior, equal-clock duplicate ordering, SIC carry/ownership rules, source_backed_only/FX behavior, history/fiscal_period NULL keys, event/catalog pairing, filter/counter aggregation and raw typed duplicate-preserving four-product equivalence; interrupted cache/source/code/snapshot changes must reject. Measure synthetic peak RSS/Arrow allocation and phase wall time under original guard; source actual qualification remains separately pending. No tests performed here.

## Reducing repeated financial work safely

Preserve existing all144 preparation cache and admitted85 extraction receipts. Reuse one guarded connection and eligible session across multiple batches using existing selected/max bounds, reducing startup/freezes/replay of previously admitted units; controller must choose a host-safe stopping quantum. Keep all original per-compute rechecks and final admission replay. Reusing in-memory concepts/FX or snapshot digest calculations can reduce small overhead only if code/full actual input identities remain checked and no source mutation authority changes; existing frozen orchestration currently recreates them, so this is a future owned helper option, not an edit instruction.

Do not replace SHA checks with stat/mtime, cache source identities across independent openings without authenticated immutability, skip `admit_unit` native replay, reuse old outputs lacking at-compute start provenance, omit one of85 units or144 prep units, or promote a partial candidate. Optimizing deterministic digest serialization of a~10MB snapshot can reduce Python churn, but changing frozen helpers is outside current authorization and probably less impactful than batch buffering/longer sessions; benchmark before proposing it as the primary fix.

## 13F archive/index and bounded inventory

`_submissions_archive.SubmissionsArchive.__init__` fully hashes original archive on EACH open, binds stat+SHA/index/python identity, opens persistent SQLite directory named by actual source SHA, verifies full index-file digest receipt and metadata identity, sets8MiB SQLite cache/file temp/no mmap. Directory framing is bounded; it does NOT retain full ZIP ZipInfo inventory. `read(name)` rereads actual selected central bytes, checks last-name-wins/header offset/overlap/CRC/expanded size, and checks archive unchanged. This already solves full central-directory memory accumulation.

`thirteenf_quality.inventory_submissions:134` privately subclasses read-only archive; missing/corrupt index is refused instead of rebuilt. It opens a fresh authenticated archive for each partition, bounds main members<=10,000 and individual expanded JSON<=4MiB, emits recent and EVERY referenced public history chunk, drops full main JSON before history, records missing/corrupt references and full expected partition boundaries. It retains `source_completeness=UNQUALIFIED_PARTITION`. End output/receipt is published only after normal traversal; stopped.partial output is not a partition receipt or completed cohort. Main member bounds are lexicographic after/through; complete expected CIK coverage must remain gapless/nonoverlapping and archive-identical.

Existing persistent index avoids repeated directory reconstruction. **Redundant cost remaining is full archive SHA plus full index digest on every separately opened partition**, plus repeated caller audits if orchestration also authenticates the same archive. Reducing partition size improves interruption loss but magnifies repeated full hashing. Source full hashing is required on every independent open; removing it or trusting stat would weaken admission and is not recommended.

Smallest safe next helper design: one externally guarded read-only `SubmissionsArchive` session authenticates complete original archive and existing directory once; iterate several independently bounded after/through partitions using unchanged `submissions_inventory` and actual selected member reads. Persist each completed partition output and independently pinned receipt with archive/index/code/source session identities, actual output bytes and complete traversal exceptions, then recheck original archive bytes and index/full receipt at session/public boundary. No full archive hash omission: retain authenticated session start/end full hashes and actual selected central/member checks. This avoids reopening/reindex verification per partition while allowing completed partition retention during later work. Existing `inventory_submissions` accepts only archive path, not an open session; a new owned bounded inventory adapter must implement the session orchestration, not monkeypatch its subclass.

If session stops before final full-byte authentication, partition files are private pending outputs until independent full archive/index authentication and replay admit them; they are not self-certified completed inventory. Cross-process reuse requires independently pinned immutable archive/index/code and explicit full authentication, not a receipt generated solely by the new reader. Preserve official source/receipt provenance, absence/history diagnostics, duplicate-name semantics, full expected accessions and unresolved public clocks. Raw submissions Z strings remain leads; qualified acceptance requires original EDGAR Accepted/header cross-check. Faster inventory does not create qualified ownership (native13F producer still hardcodes UNQUALIFIED).

Proof required: synthetic duplicate filename/overlap/CRC, central-record tamper, source rewrite with restored mtime, changed/corrupt index and digest, stopped index publication, stopped partition publication, missing history references, max-member bound, same exact partition cells/counters/order and complete partition axis. Current frozen directory helper already provides core security checks; retain them. No implementation/tests or source authentication were performed in this analysis.
