# Quant research workflow gap: generic PIT fundamental signal deciles

Read-only code review on `feat/tier1-parity`, 2026-09-23. This is an implementation brief, not a claim that the current incomplete warehouse has a usable historical sample or that any signal has alpha.

## Existing callable paths

| Path | Capability and limit |
| --- | --- |
| `api/service.py::issuer_content_range` and `asof/fundamentals.py::issuer_derived_asof` | Bounded, CIK-owned issuer accounting history with a content cutoff, selected source owner and nullable derived revisions. It answers one issuer lookup, not a daily cross-section or forward outcome question. |
| `panel_export.py::export_panel_quarterly` / `scripts/export_panels.py` | Deterministic wide Parquet snapshot by `(security_id, period_end)` using selected standardized and derived metrics. Its single export cutoff does not select the value known on each earlier trading decision date. `export_panel_daily_market` is a separate price panel; there is no joined daily fundamental signal or forward evaluation. |
| `derived_registry.py` and `derived_metric_values` | Declarative metric codes/windows, definition hashes, event clocks, NULL invalidations, history/value status, fiscal operand dates and lineage. This is the right source for a new fundamental signal panel. Rows from legacy history must remain ineligible for strict PIT evaluation. |
| `derived_factor_projection.py::load_projection_inputs` | An existing monthly factor projection of one metric onto a governed grid, including a state fingerprint. It is narrower than daily, multi-input research; the projected metric state must still be checked for history, definition, currency and owner suitability. |
| `factor_panel.py`, `alpha_research.py`, `scripts/build_alpha_research.py` | Earlier factor/alpha path. Some readers use `is_latest_revision`, and the default alpha specs are three fixed price expressions with missing z-scores coalesced to zero and minimum cross-section five. It is unsuitable as the strict historical accounting evaluation baseline without changing those contracts. |
| `custom_features.py::refresh_custom_features` / `evaluate_custom_features` and `scripts/build_custom_features.py` | CF1 builds eight fixed price/liquidity signals, pins build/evaluation runs, ranks before outcome joins, evaluates 5/21/63 session forward returns, records attrition, applies calendar-aware HAC and an eight-test Holm correction. The schema and evaluator are tied to the eight wide columns and fixed dictionary; they cannot ingest an arbitrary fundamental metric or proprietary combination. Its own documentation explicitly withholds production certification. |
| `sql/research/fundamental-desk-screen-acceptance.sql` / `custom-feature-decile-acceptance.sql` | Carefully pinned read-only desk screens and CF1 acceptance. The desk query has four literals and one date; the decile query reads CF1 results. Neither is a reusable daily signal experiment. |

## One next implementation

Add **a file-backed fundamental signal research run**: a deterministic long `(decision_date, security_id, signal_id)` panel from reconstructed derived metric event states, followed by 5/21/63-session decile spreads against the existing survivorship-safe label table. The deliverable is an inspectable Parquet panel, compact decile/evaluation artifacts and a JSON manifest. It must fail closed on missing prerequisites, preserve excluded-name/date diagnostics, and never mark a signal production eligible. Start with dimensionless, registered accounting ratios and linear combinations of them. This is a usable cross-sectional research path for a quant team without adding a second accounting publisher or rewriting CF1.

**Files, disjoint from the operator-status work:** add `atx-db/src/atx_db/fundamental_signal_research.py`, `atx-db/scripts/research_fundamental_signals.py`, and `atx-db/tests/test_fundamental_signal_research.py`. Keep `custom_features.py`, `build_custom_features.py`, API, migrations, and `cli.py` unchanged. Reuse `calendar_hac_statistics` as a pure helper; implement a general Holm family in the new module because `holm_eight` is intentionally fixed to CF1. Do not write into CF1 tables or reuse CF1 run IDs.

**Public interface:** `build_fundamental_signal_panel(store, options: FundamentalSignalResearchOptions) -> FundamentalSignalResearchResult` and `evaluate_fundamental_signals(store, *, panel_manifest: Path, label_source: str, evaluation_as_of: date, out_dir: Path) -> FundamentalSignalResearchResult`. The script exposes `build` and `evaluate`, with `--db-path`, `--start-date`, `--end-date`, `--as-of-date`, `--run-id`, `--signals-json`, `--out-dir` for build, and `--panel-manifest`, `--label-source`, `--evaluation-as-of`, `--out-dir` for evaluate. Require an existing migrated warehouse, explicit UTC cutoff, finite date range, and bounded signal count. Example spec: `{"signal_id":"quality_mix_v1","direction":1,"terms":[{"metric_code":"operating_margin","metric_window":"ttm","weight":0.5},{"metric_code":"roic","metric_window":"ttm","weight":0.5}],"max_age_days":200}`. Signal specs are frozen before inspecting labels; duplicate IDs/codes, nonfinite weights and missing definition contracts error. Support a single term as the common case. The manifest stores canonical sorted spec JSON and SHA256, dataset/source identifiers, schema/query hashes, build snapshot, cutoff policy and prerequisite counts.

**Decision and data contract:** build the actual observed market-session calendar in SQL. A decision at 22:00 UTC on session T may use a derived state visible by that cutoff and market/cohort facts observed by then; enter at the next observed session close. Select historical US common membership at T from `universe_us_listed_membership`, quarantine overlapping membership intervals, and require an unambiguous dated CIK link when claiming issuer-qualified fundamentals. Do not use today's `is_latest_revision` to reconstruct T. Within each `(security_id, metric_code, metric_window, target_bucket)` rank complete visible event rows by event availability and stable ID *before* checking `value_status`; then choose the newest fiscal period whose current state is visible. A newer NULL/unavailable state must not reveal an older numeric revision. Enforce `period_end` and fiscal operand end `<= T`, `available_at <= decision_at`, reconstructed history, registered definition/version/hash, finite value and configured age. Preserve selected `derived_value_id`, `inputs_hash`, `definition_hash`, `value_origin`, period and clock in the panel, with per-leg exclusion reason. Do not silently fill missing legs or z-scores with zero. Set whole signal NULL when any leg is ineligible, and keep a count/status row for each date/cohort to expose survivorship and coverage. Prefer SQL partitions/temporary tables; do not materialize all names/dates in pandas.

**Currency and units:** no FX conversion and no mixing raw currency amounts. `derived_metric_values` has no currency/unit field, so the first version accepts an audited allowlist of dimensionless registry metrics only (ratios, margins, yields and explicitly unitless changes); the allowlist is code-reviewed rather than asserted by the caller. Reject monetary levels, per-share currency values and unclassified metrics until a currency/units lineage contract exists. Weighted terms must have compatible dimensionless meaning; publish each term and weight in the manifest. No positive-value assumption: negative margins and growth are valid finite values.

**Outcome contract:** verify the Parquet SHA256 and frozen build manifest, source calendar digest and label-source/horizon prerequisites before evaluation. Reproduce CF1's honest timing: rank finite eligible scores by `(score, security_id)` within a decision date; require at least 200 names and 20 per decile, detect constant scores, freeze deciles before joining labels by exact `(security_id, entry_date, horizon)`, choose latest visible label revision before validity checks, require mature end date and valid terminal policy. Carry empty/insufficient/embargo/purged dates and label attrition to a compact decile artifact. Compute Q10 minus Q1 date spread, calendar-aware HAC lag `horizon-1`, predeclared train/validation/holdout splits with boundary purge and 63-session embargo, all requested horizon results including failures, and Holm adjustment over the number of *predeclared primary 21-session signals* per split. Report 10/25/50 bp-per-side scenarios and annual/date counts as research diagnostics, not portfolio PnL. Record modeled filing availability, incomplete source backfill, ownership/terminal-label gaps and transaction/borrow uncertainty as blockers; `production_eligible=false` throughout.

**Focused tests:** a tiny fixture with two decision dates, two securities plus enough synthetic names for a qualifying decile date, a late filing, a visible numeric revision followed by NULL invalidation, stale/legacy/definition-mismatch states, an overlapping membership and ambiguous CIK. Assert exact selected state IDs, that invalidation prevents resurrection, age and clock exclusion, negative dimensionless values retained, deterministic rank tie-break, same file/manifest hash across repeated build, no rank change after missing-label joins, and label revision/terminal attrition. One statistical unit case checks irregular-calendar HAC and a variable-size Holm family; one CLI validation case rejects monetary/unclassified metrics. Use in-memory/temp DuckDB fixtures; no live warehouse or source replay.

**Acceptance limit:** completing this path produces defensible *research evidence*, only after source facts, memberships and forward labels actually exist across the requested historical range. Empty/incomplete coverage must be an explicit result, never an alpha claim. The current source backfill and CF1 live evaluation are incomplete, so no performance estimate can be inferred from this review.
