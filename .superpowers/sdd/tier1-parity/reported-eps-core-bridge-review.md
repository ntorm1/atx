# Reported EPS core bridge 0321 — independent static review

Reviewed `reported-eps-core-bridge-draft/integration-final.patch` at SHA-256 `9D4BC4F7A147FAA1D73853008D36EAB8685A7CA1BAAA548169BB230E94F1012B`, its implementation report/task state, the source-0320 contract, and the public CVX acceptance case. **Disposition: do not integrate this patch yet.** The three Critical findings prevent either production materialization or the required equal-clock conflict behavior. This was a static review only; no Python, tests, database, network, or live source mutations were run while the loader owns the writer.

## Critical

1. **Production statement refresh has a `UNION ALL` column-count mismatch.** Patch lines 267–308 use `SELECT r.* FROM fundamental_fact_revisions` against a fixed release projection ending at `updated_at`. Production migration `atx-db/src/atx_db/migrations/bodies_0001_0137.py:11366` appends `as_of_date` to `fundamental_fact_revisions`, beyond the base schema in `atx-db/src/atx_db/schema.py:1144`. The release arm omits this last column. The fixture in patch lines 603–642 recreates the pre-migration shape, so its source-CTE test cannot detect the production mismatch. Use an explicit, ordered projection on both arms including `as_of_date` (or deliberately exclude it from both), and test against the migrated table shape. `git apply --check` cannot detect SQL binder errors.

2. **The conflict CTE references a column it discards.** `release_eps` selects `release_accession` (patch line 362), but `visible_pairs` projects only `direct.*`, `release_statement_point_id`, and `release_value` (lines 401–403). The outer lineage expression uses `release_accession` (line 432), which is unbound. `_create_candidates` includes this CTE unconditionally, so every standardization refresh fails before publication, even when there are no EPS conflicts. Add `release.release_accession` to `visible_pairs` and bind the focused CTE test against the production statement-point columns.

3. **Equal-clock source conflict is suppressed before conflict detection.** The release arm's `NOT EXISTS` excludes a release when a matching direct CompanyFacts EPS has `direct.available_at <= p.available_at` (patch lines 323–338). If direct and release are visible at the same instant with a difference above 0.005, there is no release statement point for the conflict CTE. The later conflict-first ranking (lines 119–135) therefore cannot emit the required NULL state; the direct value silently wins. Retain both source events at an equal clock and let the conflict candidate plus same-clock ranking decide. Include this exact case in the integration test. The source contract explicitly requires an unavailable state when both visible values conflict.

## Important

1. **The supplied tests do not verify the requested production path.** Patch lines 553–602 query the isolated conflict CTE; lines 603–668 query the isolated source CTE with simplified tables. They never run release → `fundamental_statement_points` → item 1035 `fundamental_standardized` → `eps_diluted_q_growth_yoy`, nor a valid release followed by a later conflicting direct value and a derived NULL revision. Add a focused migrated-schema integration fixture with four quarters and as-of assertions before and after the direct event, both lineages, the `reported_eps_conflict` exception, equal-clock ordering, and refresh cleanup. The public benchmark in `atx-db/docs/CVX_EPS_ACCEPTANCE.md:1–110` remains an unexecuted production acceptance target for this patch.

2. **Full-universe memory cost remains unproved.** Patch lines 225–235 aggregate all `fundamental_fact_revisions` to derive unique CIK owners while lines 267–338 also union the full revision relation and run a correlated direct-EPS anti-match. At the reported roughly 47 million raw-fact scale, the existing bounded shadow publisher does not bound this input plan's hash/group/anti-join work. Preserve the exact CIK-only owner rule, but show a bounded SQL plan and measured process-tree peak under the 2 GiB guard before activating the full refresh; use scoped source relations or materialized small CIK/EPS key sets if the plan exceeds the cap. This is a capacity gate, not a claim that it already fails.

3. **Bridge admission should enforce the accepted-row qualifiers.** Patch lines 240–254 test source/form/item/metric/basis/unit/quarter/clock/CIK, but omit the source contract's `is_preliminary = true` and `extraction_confidence = 1.0` (`source-contract.md:8`). Its fixture omits those columns. Add these predicates and production-shaped fixture columns so an unrelated or malformed row using the same source string cannot be promoted to item 1035. The 0320 receipt and clock invariants still need their own source tests.

## Minor

- The patch comments say the `source_facts` CTE preserves direct and release events independently, but its direct-earlier anti-match (lines 323–338) intentionally drops some releases. After resolving the equal-clock blocker, state and test the precise policy for a direct event strictly earlier than the release. That case affects whether a later release can produce a conflict and should be explicit in the contract.

- The bridge routes releases to a unique existing CompanyFacts owner by normalized numeric CIK, without a ticker/current-security lookup (patch lines 225–235, 309–314). Its duration branches require explicit three-month evidence with 89–93 days, or exact 91/98-day 13/14-week spans (lines 315–322). It adds no FY-minus-YTD per-share construction.
- The proposed nullable `fundamental_standardized.value` migration, catalog update, and schema pin (lines 470–518) use the existing standardized table. Production `fundamental_publication` builds stages and shadows from the live table's nullability; governed optional indexes were removed by 0318, so no additional index drop is indicated by this static inspection. The issuer-query owner separately owns API/as-of nullable contracts; this review does not request edits to those files.
- `_derived_pit.prepare_security` retains whole nullable standardized states before item selection (`atx-db/src/atx_db/_derived_pit.py:56–100`). The item-coverage change ranks revision groups before filtering finite values (patch lines 155–179), and provider coverage checks latest revision before finite value (lines 184–197). Those paths look structurally compatible once the Critical blockers are fixed, but the missing integration test still must prove actual derived NULL propagation.
- 0321's registry/hooks are deliberately deferred until root serializes it after source 0320. This is an integration dependency, not a draft defect.
