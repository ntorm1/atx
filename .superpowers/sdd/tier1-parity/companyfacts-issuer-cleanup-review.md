The old predicate was existential over an old fact whose keys match and whose own ID or a legacy ID matches the point. Distributing that existential across the identity alternatives produces exactly this union. Old resolved IDs are never collected and crossed with unrelated old keys.
- **NULL and type contracts.** Point ID matching remains ordinary equality (`1247`), so a NULL point ID cannot match a NULL old ID. Removing NULL IDs from the staged relations does not remove a previously true match. All six filing keys retain `IS NOT DISTINCT FROM`, including the metric/concept mapping (`1248-1253`). The key columns inherit their fact-table types; the passed legacy IDs are explicitly VARCHAR, agreeing with raw facts, points, and ticker schema definitions. Date keys remain DATE. No return or parameter type contracts change.
- **Issuer and source scope.** The guarded numeric CIK predicate is unchanged for staging, ticker IDs, raw-fact deletion, and candidate cleanup. Unrelated IDs with identical keys survive. As before, points containing the same source, ID, and all six keys cannot distinguish separate CIK ownership because points have no CIK; this patch does not widen that pre-existing equivalence class. The raw-fact and candidate cleanup predicates are unchanged.

An empty successful replacement therefore still clears matching old evidence, while an issuer with no old facts supplies no deletion tuples. The implementation adds no warehouse-wide Python fetch or materialization. Its expanded SQL relation is bounded by this issuer's own ID/key tuples plus its distinct filing keys times its deduplicated legacy IDs. Large issuers and numerous legacy IDs can still increase this bound; the rewrite does not prove the absence of all possible OOMs or eliminate repeated table scans.
