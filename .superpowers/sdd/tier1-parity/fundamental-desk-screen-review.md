# Independent static review: fundamental desk screen

Reviewed `fundamental-desk-screen-draft/integration-final.patch`, `implementation-report.md`, and `task-state.md` against `fundamental-desk-screen-brief.md`, the production table definitions, seed, and producing SQL. This is a **prepared, unexecuted** acceptance artifact. No warehouse query, import, Python, test, network call, or production mutation was used in this review; every count and production coverage gap remains unmeasured.

## Findings

1. **High — EPS owner check can certify the wrong source row.** The `eps_owner_evidence` CTE at SQL lines 141–161 filters `fundamental_standardized` to rows whose CIK equals the dated identifier **before** choosing a row, then accepts any same-security, same-period quarterly EPS row available by `d.eps.available_at`. The derived publisher selects an EPS input state by `(period_end, available_at, source, rule_id, basis, standardized_id)` within its quarter bucket (`atx-db/src/atx_db/_derived_pit.py`, lines 73–89), and the selected row's ID is included in the derived `inputs_hash` lineage (lines 130–143, 297–301). If a later eligible EPS row with another CIK wins that selection, an earlier matching-CIK row still makes `eps_owner_status='valid'`, so `complete_rows` can include an unqualified source owner. Rank the whole eligible EPS input state under the publisher's rules at the selected derived event, then compare its CIK/security/period to the dated link; preferably expose or verify the selected standardized ID in the derived lineage. Count an owner mismatch separately. Preserve the existing refusal to infer a CIK from the current ticker directory.

2. **High — accounting freshness can be overstated for annual fallback.** SQL lines 196, 203, 210, and 217 apply the 200-day gate to `derived_metric_values.period_end`. In the canonical publisher, `period_end` is the output target quarter while `fiscal_period_end` records the selected operand span (`atx-db/src/atx_db/_derived_pit.py`, lines 307–325); migration 0316 explicitly says those fields differ for exact fiscal-year fallback. A September 2026 target quarter can therefore pass this gate while its actual annual operand ended in December 2025. For trailing margin, accruals, and leverage, gate the relevant selected fiscal end and report both target and operand ages; classify missing operand span as unavailable. Keep quarterly EPS tied to its actual quarter. This is an acceptance freshness rule, not an alpha threshold.

3. **Medium — definition version pin does not qualify selected rows.** `contract` counts four registry codes with version `1` (SQL lines 16–23), but `metric_states` admits every row with the pinned source/code/window (lines 99–140), regardless of its `definition_hash`. The publisher explicitly computes a fingerprint from expression, inputs, version, and annual plan (`_derived_pit.py`, lines 38–43), and writes it per state (lines 312–325). A surviving state from a previous definition can be marked complete merely because the registry currently has version `1`. Pin/check the four expected definition hashes, or otherwise verify each selected state's hash against the frozen definition build, with a named mismatch count/status. Do not filter old hashes before ranking, because doing so could expose an older valid state.

4. **Medium — missing-field diagnostics are priority-dependent.** `market_status` at SQL lines 178–188 reports the first failed market field, and the aggregate's `missing_earnings_yield`/`missing_cfo_to_ev` counts at lines 255–257 use that single status. A row with invalid market cap and absent CFO yield is absent from the CFO missing count; an absent earnings yield similarly hides absent CFO yield. This prevents the aggregate from answering exactly which required market inputs are absent for otherwise eligible names. Add independent per-field NULL/nonfinite counts alongside the first-failure disposition, including invalid close and cap counts. The existing raw state in each preview is useful and should remain.

5. **Medium — overlapping membership can silently select a qualifying state.** `members` at SQL lines 25–44 ranks all visible intervals per security with `arg_max`; `cohort` then accepts whichever state won. The production universe contract expects nonoverlapping intervals and registers overlap as a critical quality check (`bodies_0304.py`, lines 15–42 and 101–130), but the readout itself would hide a conflicting visible noncommon interval and report a complete common-equity name. Count overlapping or conflicting visible membership states and fail or quarantine those securities before cohort selection. This also gives a named membership-data failure when the production interval invariant is broken.

## Static checks that passed

- The actual seed has the four requested code/window/version pairs (`atx-db/src/atx_db/seeds/derived_metric_definitions.csv`), and the production source names and `us_listed_v1` identifier match the SQL pins.
- Referenced columns are present in the production schemas (`bodies_0302.py`, `bodies_0304.py`, `bodies_0315.py`, `bodies_0316.py`, base `schema.py`, and `fundamental_standardized` migration). No obvious missing-column binder defect was found statically; DuckDB execution remains the required binder check after the guarded writer releases the database.
- The metric `arg_max` arguments are whole structs, so a visible NULL/conflict value remains selectable rather than causing an older numeric value to resurface. The market row uses its own `available_at`, and the output reports the observed trade date rather than treating Sunday 2026-09-20 as a session.
- The aggregate is built from scalar aggregates and should emit a row for empty membership. Named empty statuses are present. The name preview is capped at 333 rows in each of three dispositions (999 total), with deterministic ordering; no forward-return or alpha claim appears.
- The CIK link is date/cutoff constrained, the current directory CIK is not used as a join, and display ticker is sourced separately from a dated listing. Whether the actual production identity coverage supports this gate is unmeasured.

Resolve the two high findings before treating `complete_rows` as accepted names. The root runtime owner can then execute the frozen artifact once, record the SQL hash and actual aggregate/preview, and make only observed bounded source fixes.
